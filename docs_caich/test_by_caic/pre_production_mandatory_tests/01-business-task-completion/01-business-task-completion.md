# 01 业务任务完成率

## 1. 目标

直接验证 Agent 能否完成用户业务目标。意图准确率、工具准确率和参数准确率只作为失败诊断指标，不能替代任务完成率。

## 2. 主指标

| 指标 | 定义 | 门槛 |
|---|---|---:|
| 首轮任务完成率 | 无需补充信息，一轮完整完成的任务数 / 可首轮完成任务数 | 记录基线 |
| 最终任务完成率 | 允许合理澄清，在限定轮数内完整完成的任务数 / 总任务数 | `>= 95%` |
| 澄清恢复率 | 正确追问后，用户补齐信息并最终完成的任务数 / 需澄清任务数 | `>= 95%` |
| 复杂任务完成率 | 多工具、多步骤请求完整完成数 / 复杂任务数 | `>= 90%` |
| 伪完成率 | Agent 声称成功但工具未成功的任务数 / 总任务数 | `< 1%`，写操作 `0%` |
| 写操作误执行率 | 缺参、冲突、未授权时仍执行写工具的任务数 / 对应用例数 | `0%` |
| 重复写调用率 | 同一业务动作被 Agent 重复发起的次数 / 写任务数 | `0%` |

## 3. 分业务门槛

| 业务类别 | Agent 侧最终任务完成率 | 特殊要求 |
|---|---:|---|
| 工时明细查询 | `>= 97%` | 人员、项目、时间范围正确 |
| 工时统计 | `>= 95%` | 不把明细查询误当统计 |
| 项目查询 | `>= 97%` | 名称与 ID 解析正确 |
| 单条工时填报 | `>= 99%` | 错误执行和伪完成均为 0 |
| 批量工时填报 | `>= 95%` | 记录拆分、日期、工时和 dry-run 正确 |
| 周报生成 | `>= 95%` | 汇总内容与工具结果一致 |
| 知识库问答 | `>= 90%` | 同时满足 RAG 专项门槛 |
| 多工具复杂任务 | `>= 90%` | 不允许只完成部分子任务后声称成功 |

## 4. 必测场景

### 4.1 单轮

- 普通聊天：正确直接回答，不误调业务工具。
- 查询本人、他人、指定项目、指定时间范围的工时。
- 统计总工时、占比、排名、漏填和加班。
- 项目查询和模糊项目名解析。
- 单条填报：完整参数、缺项目、缺日期、缺时长、参数冲突。
- 批量填报：列表、表格、多项目、多日期、部分不可解析。
- 周报和知识问答。
- 空输入、仅标点、错别字、口语、繁体、英文混合、emoji 和长文本。

### 4.2 多轮

- 缺参逐轮补齐。
- “上周呢”“还是那个项目”等参数继承。
- 用户纠正日期、人员、项目和时长。
- 查询任务切换为填报任务时清除旧参数。
- 用户身份或查询主体切换。
- 闲聊打断后恢复原任务。
- 工具失败后用户修改参数重试。

### 4.3 复杂任务

- 一次请求需要两个以上只读工具。
- 查询后统计、比较并汇总。
- 多文档知识问题需要多步检索。
- 达到最大循环次数、重复调用检测和部分工具失败。

## 5. Agent 侧成功判定

SpringBoot 和数据库不由 Agent 团队实现，因此使用契约 Mock 或隔离联调环境判定：

```text
用户目标
  → Agent 选择正确路径
  → 发出正确且唯一的下游请求
  → Mock 按契约返回成功/失败/空结果
  → Agent 返回与该结果一致的 SSE 和最终答复
```

写操作只要请求体、身份信息、调用次数、dry-run 和响应处理正确，即可记为“Agent 侧完成”。真实落库状态另由联合 E2E 验收。

## 6. 子指标与失败类型

每条失败必须归入至少一种原因：

- `wrong_intent`
- `wrong_tool`
- `missing_tool`
- `wrong_param`
- `unnecessary_clarification`
- `missing_clarification`
- `context_contamination`
- `duplicate_tool_call`
- `partial_completion`
- `tool_error_misreported`
- `false_success`
- `unsafe_execution`
- `loop_not_converged`
- `response_inconsistent`

## 7. 测试数据与重复规则

- 单轮盲测集不得少于 200 条，并覆盖所有生产工具。
- 多轮会话不得少于 100 段，每段 3～6 轮。
- 每个 P0 写操作场景至少重复 10 次。
- 普通单轮用例至少重复 3 次，多轮会话至少重复 5 次。
- 同一重复组必须使用独立 `session_id`，禁止历史污染。

## 8. 结果表最小字段

```text
case_id, category, risk_level, user_goal, input, session_id,
expected_path, expected_tools, expected_params, expected_final_state,
actual_path, actual_tools, actual_params, actual_response,
tool_call_count, clarification_count, completed, false_success,
unsafe_execution, failure_type, ttft_ms, e2e_ms, raw_log_ref
```
