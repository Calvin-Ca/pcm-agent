## 本轮代码修复

1. 所有写操作执行前统一校验当前轮授权、必填参数、日期、时长和预览确认。
2. 批量写首次强制 dry-run；只有明确确认且上一轮预检成功时才允许真实写入。
3. “不要 dry run”“直接保存”等绕过预览的表达按用户原话拦截，不能依赖模型是否生成 `dry_run=false`。
4. 批量引用语句没有完整明细或预览指令时只追问，不执行工具。
5. 断连、超时和失败结果不再包装成成功；错误消息优先使用工具返回的 `message/error`。
6. `query_timesheet`、`compute_statistics`、`generate_weekly_report`、`save_workhour` 支持 `member_name`，在工具内部解析真实成员 ID。
7. 统计、周报、建议、项目比较、多月份拆分等常见意图增加确定性归一化。
8. 确定性工具调用不再跳过统一的身份、Schema 和日期归一化。
9. 修复当前月与当前周边界混用、自然周类型、相对星期、季度逐月展开等问题。
10. `query_project` 的“名称或 ID”契约与实现对齐，项目名称先解析为真实 ID；HTTP 状态错误不再伪装成“未找到”。
11. 评测器的 `--confirm-reviewed` 改为幂等操作，重复评测不再改写数据集和哈希。
12. 安全指标区分 dry-run 预览与有效写入，避免把不会落库的预览误报为未授权写入。
13. Redis 会话新增同 TTL 的结构化业务状态，保存最近工具、已确认参数、预检结果和多工具计划；明确排除 `auth_token` 等凭据。
14. 多轮确认、参数更正和上下文继承优先使用结构化状态，不再只从助手可见回复反向猜测。

## 仍不能由代码合法修复的测试集/契约冲突

以下问题若通过硬编码满足，会使生产行为变错，因此本轮未做针对性代码适配：

1. `SGT-002`：基准日 2026-08-07 是星期五，“上周四”应为 2026-07-30，数据集期望 2026-07-31。
2. `WRITE-CONFIRMATION-007`：同一基准日下“上周三”应为 2026-07-29，数据集期望 2026-08-05。
3. `CLARIFICATION-COMP-004`：批量预览工具需要上一轮真实工时明细，数据集却要求把 `text` 设成“预览一下，别真存”。
4. `STA-014`：“按各种工作类型分别统计”被期望为 `daily_hours`，与统计维度语义不一致。
5. 多条审批用例要求调用输入中从未出现、上游结果也未返回的 `wh_xxxx` 记录 ID；Agent 不应猜测审批 ID。
6. 部分查询用例要求查询未来日期、无效日期或超过 Agent 当前 90 天边界，和现有安全策略冲突。
7. 部分项目周报用例要求项目过滤，但 `generate_weekly_report` 当前 Schema 没有 `project_id`。
8. 多轮用例多次要求继承前文不存在的内部 ID；结构化会话状态已经实现，但它只能保存真实出现或真实解析出的值，不能安全生成从未出现的 ID。

## 上线判断

P0 写安全可以判为通过，但业务完成率不能判为通过。上线前至少还需要：

1. 修订并重新审核上述矛盾数据；
2. 明确未来日期、项目周报、审批 ID 获取的产品契约，并让测试集只依赖真实可获得的数据；
3. 在修订后的固定哈希数据集上重新执行一次完整 420 条评测。
