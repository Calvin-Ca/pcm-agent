# RAG 混合检索、查询改写与重排序实验验证报告

> 对应方案：[rag_hybrid_retrieval_experiment_validation.md](rag_hybrid_retrieval_experiment_validation.md)  
> 实验日期：2026-08-06 至 2026-08-07  
> 报告状态：自动实验完成；答案裁判人工复核待完成

## 1. 摘要

本实验在扩充后的知识库和 200 条冻结评测集上，对向量检索、BM25、RRF 混合召回、查询改写和 GPU Reranker 进行了 A～F 六组消融。

主要结论：

- 验证集预先选出的推荐方案为 **E：向量 + BM25 RRF + Reranker**。
- 盲测中，E 相对纯向量 A 的 Recall@5 提升 **6.48 个百分点**，MRR@10 提升 **13.73 个百分点**，nDCG@10 提升 **10.35 个百分点**；三项配对 Bootstrap 95% CI 均支持排序增益。
- 完整方案 F 的 Recall@10、MRR@10 和 nDCG@10 最好，但 Recall@5 略低于 E，且增加约 1 秒查询改写延迟，因此不作为当前推荐配置。
- E 的答案事实正确率由 **90.12%** 提升到 **93.01%**，要点覆盖率由 **86.46%** 提升到 **89.69%**，无依据陈述率由 **13.91%** 降至 **10.59%**。
- 无答案正确拒答率仅 **33.33%**，明显低于 95% 验收线，是当前最主要失败项。
- 方案中设定的 Recall@5、复杂/多跳覆盖和答案覆盖率增益阈值均未达到，因此本轮整体判定为：**部分通过，不满足完整验收标准**。

## 9. 结果边界与风险

1. 200 条问题由 `qwen3-8b` 基于当前知识库生成，随后人工确认；虽然比旧 4 文档/50 问题基准更有效，但仍可能带有合成数据分布偏差。
2. 回答质量由 LLM 裁判评分。按照原方案，仍需人工复核全部失败案例和随机 20% 通过案例，才能报告裁判与人工一致率。
3. 当前检索实验以相关 chunk ID 为真值。多跳 Recall 可反映两个来源 chunk 的覆盖，但未另外输出“文档级覆盖率”字段。
4. 无答案错误召回率没有定义可校准的分数阈值；本轮直接检验最终拒答行为。
5. 初次盲测在第 99 条遇到一次网络连接重置，未产生报告；增加 API 重试后按相同冻结参数完整重跑 108 条，最终报告来自成功的完整重跑。
6. 验证集选择 E 后未再根据盲测结果修改融合或重排参数，避免盲测泄漏。

## 10. 推荐改进顺序

1. 增加答案存在性判断：基于 Reranker 绝对分、Top1/Top2 margin、跨路一致性和证据充分性分类器，在开发/验证集校准拒答阈值。
2. 对长尾和多跳失败案例做检索错误分析，补充口语化改写、实体别名词典和分解式多跳查询。
3. 查询改写改为按意图触发，而不是所有请求固定执行；优先用于长尾和多跳场景，避免约 1 秒固定延迟。
4. 将 E 作为默认方案，将 F 作为复杂问题的条件分支。
5. 完成人工裁判复核，报告一致率并修正自动评分偏差。
6. 增加困难负样本误排率、生成 TTFT、完整 E2E P50/P95 和准确 token 统计。
7. 将本轮失败问题固化为回归集，优化后重新运行验证集；只有配置再次冻结后才能重新开启新的盲测集。

## 12. 指标与算法解释

### 12.1 BM25

BM25 是基于关键词匹配的经典稀疏检索算法。它主要考虑：

- 查询词是否出现在文档中；
- 查询词在当前文档中出现的频率；
- 查询词在整个知识库中是否稀有；
- 文档长度，避免长文档仅因包含更多词而天然占优。

一个词在问题和文档中同时出现，并且该词在整个知识库中较少见时，通常会获得更高权重。因此，BM25 比较适合制度名、项目名、编号、接口名、日期和低频专有词等需要精确匹配的场景；对于同义改写或没有复用原文关键词的问题，BM25 通常弱于向量检索。

本实验中的 B 组只使用 BM25，C～F 组将 BM25 与向量检索结合。

### 12.2 RRF

RRF（Reciprocal Rank Fusion，倒数排名融合）用于合并多路检索结果。它主要使用候选在各路检索中的排名，不直接比较向量相似度与 BM25 原始分数，因此可以避免不同评分尺度难以对齐的问题。

单个候选的融合分数为：

```text
RRF_score(d) = Σ 1 / (k + rank_i(d))
```

其中：

- `d` 是候选 chunk；
- `rank_i(d)` 是候选在第 `i` 路检索中的排名；
- `k` 是平滑常数，本实验取 60；
- 候选在多路结果中都靠前时，融合分数会更高。

例如，同一个 chunk 在向量检索中排第 2、BM25 中排第 3，通常会比只在单路排第 1、另一条检索完全没有命中的 chunk 更稳定地排在融合结果前列。本实验的 C～F 组均使用 RRF。

### 12.3 MRR

MRR（Mean Reciprocal Rank，平均倒数排名）衡量每个问题的**第一个正确结果出现得有多早**。

单个问题的得分为：

```text
RR = 1 / 第一个相关结果的排名
```

例如：

| 第一个正确结果的位置 | RR |
|---:|---:|
| 第 1 名 | 1.00 |
| 第 2 名 | 0.50 |
| 第 3 名 | 0.33 |
| 第 10 名 | 0.10 |
| Top 10 没有正确结果 | 0 |

MRR 是所有问题 RR 的平均值，范围为 0～1，越高越好。它适合回答“用户最先看到的正确证据是否足够靠前”，但只关注第一个相关结果，不反映其余相关结果的排序。本报告使用 MRR@10，即只检查前 10 个候选。

### 12.4 nDCG

nDCG（Normalized Discounted Cumulative Gain，归一化折损累计增益）衡量**整个结果列表的排序质量**。

其核心逻辑是：

- 相关结果有正向收益；
- 排名越靠后，收益按对数折损；
- 如果一个问题有多个相关 chunk，每个相关 chunk 都参与计算；
- 最后除以理想排序的 DCG，将结果归一化到 0～1。

简化表示为：

```text
DCG@K = Σ relevance_i / log2(i + 1)
nDCG@K = DCG@K / IDCG@K
```

其中 `IDCG` 是把所有相关结果放在最前面时的理想 DCG。nDCG 越接近 1，表示相关结果越完整、越集中地排在前列。

MRR 与 nDCG 的区别是：MRR 只关心第一个正确结果；nDCG 会综合考虑前 K 名中所有相关结果的位置。因此，多跳问题存在两个以上相关 chunk 时，nDCG 通常比 MRR 更有解释力。本报告使用 nDCG@10。

### 12.5 Bootstrap

Bootstrap（自助法）是一种通过重复抽样估计指标不确定性的方法。它不要求预先假设指标差值服从正态分布，适合检索指标这类离散且分布不规则的数据。

本实验使用**配对 Bootstrap**：

1. 对同一批盲测问题进行有放回抽样；
2. 每次都同时取出 A 和目标方案在这些问题上的指标；
3. 计算两种方案的平均指标差值；
4. 重复 10,000 次；
5. 取差值分布的第 2.5% 和第 97.5% 分位数作为 95% 置信区间。

使用配对方式，是因为 A、E、F 等方案面对的是相同问题，可以直接比较同一道题上的增减，减少问题难度差异带来的噪声。

结果解释示例：

```text
E 相对 A 的 Recall@5：+6.48pp
95% CI：[+0.93pp, +12.50pp]
```
