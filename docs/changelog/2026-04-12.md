## 任务一：诊断并修复 kq_（知识问答）退步

### 问题描述

知识问答（knowledge_qa）通过率从 v2 的 72.0% 下降到 v3 的 66.5%（−5.5%，67 条失败）。

退步时间点：v3 启用了 vLLM `--tool-call-parser hermes`。

### 假设根因

hermes tool parser 启用后，vLLM 会更激进地输出 `tool_calls`，导致原本应走 RAG 路径（`execute_rag` 节点）的知识问答，被 LLM 错误映射到工具调用，从而返回 `intent=tool_execution`，而测试期望是 `intent=knowledge_qa`。

### 执行步骤

1. **读取测试数据**：`fastapi-service/tests/data/knowledge_qa/`，找 5–10 条失败 case，确认 actual `intent` 是 `tool_execution` 还是 `general_chat`

2. **确认根因路径**：
   - 若 actual=`tool_execution`：hermes 把知识问题映射到了工具 → 修 system prompt
   - 若 actual=`general_chat`：LLM 把知识问题当闲聊 → 补 few-shot 强化 knowledge_qa 触发条件

3. **修复方案（二选一）**：

   **方案 A — 强化 system prompt 中的 knowledge_qa 规则**

   文件：`fastapi-service/app/prompts/system.yaml`

   在现有规则中补充：知识问答的触发条件要明确列出，避免被识别为工具调用。示例：
   ```
   遇到以下类型的问题，使用 knowledge_qa 路径（不要调用工具）：
   - 询问考勤规则、制度、政策
   - 询问操作流程、审核流程
   - "什么是..."、"如何..."、"规定是..."类问题
   ```

   **方案 B — 在 kq_ few-shot 中加消歧示例**

   文件：`fastapi-service/app/prompts/intent_classify.yaml`（或对应的 few-shot 文件）

   在 knowledge_qa 的 few-shot 示例中，新增与工具调用相似但应走 RAG 的边界案例。

4. 修复后**不用跑全量测试**，用 kq_ 子集验证：
   ```bash
   pytest tests/test_classification_accuracy.py -k "kq_" -v
   ```

## 任务二：诊断并修复 qsbp_（按项目统计）近零问题

### 问题描述

query_statistics_by_project 通过率 6.0%（3/50），95% 的 case 被分类为其他意图。

### 假设根因

`qsbp_` 和 `qspm_`（项目月统计，68.8%）的语义高度重叠，LLM 几乎总是选择 `qspm_` 或其他统计类意图，而不是 `qsbp_`。

### 执行步骤

1. **读取测试数据**：`fastapi-service/tests/data/query_statistics/`（或对应的 qsbp_ 数据文件），取 5 条 case，确认测试期望的 `intent` 和 `tool_name`

2. **确认 qsbp_ vs qspm_ 的差异**：
   - `qsbp_`（query_statistics_by_project）：按项目维度统计，重点是"某项目的工时/人员情况"
   - `qspm_`（query_statistics_project_monthly）：按项目 × 月份的交叉统计
   - 读 `fastapi-service/app/tools/` 下的对应工具 schema，确认两者描述是否足够区分

3. **修复方案**：

   **方案 A — 调整工具 description，增加区分度**

   找到 `compute_statistics.py`（或对应工具文件），修改 `qsbp_` 相关工具的 `description` 字段，加入明确区分 qsbp_ 和 qspm_ 的文字。

   **方案 B — 在 few-shot 中加消歧示例**

   在 system prompt 或 intent_classify prompt 中，为 qsbp_ 加入 2–3 条典型用例示例，并明确标注"这类问题不是 qspm_"。

4. 修复后用子集验证：
   ```bash
   pytest tests/test_classification_accuracy.py -k "qsbp_" -v
   ```
