# SQL Agent 功能上线 — 2026-04-13

## 概述

新增 **SQL Agent** 功能，支持用户通过自然语言进行复杂的数据分析查询，突破现有固定工具接口的局限。

### 解锁场景示例

```
"统计各部门近三个月工时趋势，按下降幅度排序"
"本月工时填报最少的前10个人"
"AI平台项目每周投入多少人日"
"张三上个月都在哪些项目上花了时间"
"哪些人本周还没填工时"
```

## 架构设计

### 三层安全防护

1. **数据库只读账号**：`ai_readonly` 仅有 SELECT 权限
2. **应用层 SQL 校验**：
   - 语句类型白名单（仅 SELECT）
   - 多语句检测
   - 表白名单（7张表）
   - 列黑名单（password、id_card 等敏感字段）
   - 危险关键字拦截（INTO OUTFILE、LOAD_FILE、DROP、DELETE 等）
3. **权限约束注入**：Prompt 层根据用户角色注入 WHERE 条件

### 配置项

```python
# 数据库（空值复用 MYSQL_* 配置）
SQL_AGENT_DB_HOST = ""        # 独立只读账号
SQL_AGENT_DB_USER = ""

# LLM（空值复用 CHAT_LLM_* 配置）
SQL_AGENT_LLM_API_BASE = ""   # 可切换 qwen-plus
SQL_AGENT_LLM_MODEL = ""

# 安全配置
SQL_AGENT_ENABLED = True
SQL_AGENT_MAX_ROWS = 500
SQL_AGENT_QUERY_TIMEOUT = 30
```

## 使用方式

用户发送分析类问题时，LLM 自动识别并调用 `sql_query` 工具：

```
用户：各部门本月工时对比，按部门名称排序

→ LangGraph 识别为 sql_query
→ SQL Agent 生成 SQL（如需修正可重试1次）
→ 安全校验
→ 执行查询
→ LLM 汇总结果
→ 自然语言回答
```

## 已发现/修复的问题

### vLLM thinking 内容污染 SQL 输出

**问题**：vLLM qwen3-8b 默认输出 `<think>...</think>` 推理内容，导致 LLM 返回的不是纯 SQL，而是夹杂 thinking 的文本。

**根因**：qwen3 系列模型默认启用思考模式，复杂查询时 `</think>` 闭合标签有时缺失，导致正则清理失败。

**修复**：
```python
# sql_query.py - 清理 LLM 返回内容中的 thinking/reasoning 内容
generated_sql = re.sub(r"<think>[\s\S]*?</think>", "", generated_sql)
generated_sql = generated_sql.strip()
# 清理 markdown 代码块
generated_sql = re.sub(r"^```sql\s*", "", generated_sql)
generated_sql = re.sub(r"^```\s*", "", generated_sql)
generated_sql = re.sub(r"\s*```$", "", generated_sql)
generated_sql = generated_sql.strip()
```

**关键发现**：System prompt 改为英文后，vLLM 遵循 "Output ONLY SQL" 指令的概率显著提升，中文 system prompt 有概率触发 thinking 输出模式。

### compute_statistics.py Spring Boot URL 硬编码

**问题**：`compute_statistics.py` 中 4 处硬编码 `base_url = "http://localhost:8080"`，未使用 `settings.SPRINGBOOT_BASE_URL`。

**修复**：全部替换为 `base_url = settings.SPRINGBOOT_BASE_URL`。

### vLLM vs Ollama 模型选择

**问题**：Ollama qwen3 模型默认启用 reasoning/thinking，导致 SQL 生成时混杂 thinking 内容。

**结论**：SQL Agent **必须使用 vLLM**（`http://172.19.3.136:8099/v1`），vLLM 默认不输出 thinking 内容，SQL 纯净度更高。

**配置**（`.env.local`）：
```bash
SQL_AGENT_LLM_API_KEY=EMPTY        # vLLM 不校验 API Key，填任意非空值
SQL_AGENT_LLM_API_BASE=http://172.19.3.136:8099/v1
SQL_AGENT_LLM_MODEL=qwen3-8b
```

### auth_token 未传递导致 Spring Boot API 返回 401

**问题**：`compute_statistics.py` 调用 Spring Boot API 时未传递 Authorization header，且未从 kwargs 中 pop 掉 `auth_token`/`context`，导致 `StatisticsQueryParams(**kwargs)` 抛出参数校验异常。其他工具（query_timesheet、query_project、save_workhour 等）均已正确处理，唯独该工具遗漏。

**修复**：
- `compute_statistics_handler` 在参数解析前 pop `auth_token` 和 `context`
- 构建 `headers` 字典并透传给所有子函数（`_compute_user_hours_statistics` 等 6 个）
- 每个子函数的 `httpx.AsyncClient.get()` 调用添加 `headers=headers or {}`
