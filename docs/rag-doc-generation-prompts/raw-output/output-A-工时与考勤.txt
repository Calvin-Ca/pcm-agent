# 工时填报管理制度

## 1. 适用范围

本制度适用于公司全体在职员工的日常工时填报行为，包含正式员工、试用期员工、实习生和长期外包人员（合作期≥3个月）。短期外包及临时驻场人员的工时记录另行依据合作合同执行，不在本制度直接覆盖范围内。

工时填报场景涵盖：研发、测试、运维、需求调研、客户支持、培训、内部会议、招投标支持等所有与生产经营活动相关的工作时间。员工的非工作时段（如午休1小时、下午茶歇15分钟以内）不计入工时。出差当日的旅行时间，按照单程不超过4小时折算为有效工时。

本制度不适用于以下情形：高级管理岗位（VP及以上职级）的战略性工作时间、董事会及股东会议时间、外部社会活动时间。

## 2. 定义与术语

- **工时**：员工为完成工作任务所投入的实际有效时间，以小时（h）为最小计量单位，精确到0.5小时。
- **填报日**：员工对当日工时进行录入的行为日；填报日原则上等于工作发生日，最晚不超过工作发生日后的第3个自然日。
- **填报截止日**：每月对上月所有工时完成最终汇总和提交的日期，统一为次月5日24:00。
- **审核周期**：项目经理或直属上级对员工工时进行审核确认的时间窗口，原则上为提交后2个工作日内。
- **补录**：因系统故障、出差离线、特殊审批等原因未能在规定时限内完成填报的工时，事后通过补录通道进行追加录入的行为。

## 3. 核心规则

### 3.1 填报频率与时限

员工应当在每个工作日结束前完成当日工时录入，最迟不得晚于工作发生日后的第3个自然日。每月最后一个工作日须完成本月所有未填报工时的回溯录入。每月5日24:00为上月工时的最终截止时间，逾期未提交的工时将进入"待补录"状态，需要通过补录流程处理。

### 3.2 工时投入颗粒度

每条工时记录最少0.5小时，最多不得超过单日24小时（实际审核中超过12小时需备注理由）。同一员工同一日的工时合计不得超过16小时（含加班），超过部分系统将自动校验并阻断提交。员工可在单日内将工时分摊到不同项目或任务，但每项最少0.5小时。

### 3.3 项目归属与任务关联

每条工时必须关联到一个明确的项目（含内部项目）和一个具体的任务。无项目可关联的工时（如全员培训、公司活动），统一计入"非项目工时"类别下的对应任务。员工不得在已结项3个月以上的项目下填报工时，特殊情况需先提交项目延期申请。

## 4. 例外情况

**情况一：长期出差或外派**。员工连续出差超过5个工作日的，可在出差结束后5个自然日内一次性补录全部工时，但需在出差申请中预先声明，且每周向项目经理同步进度。

**情况二：因病或紧急休假未填报**。员工因病或家庭紧急事件无法按时填报的，经直属上级在企业微信或OA系统书面同意后，可在销假后3个工作日内补报，单次补报不得超过10个工作日的工时。

**情况三：系统故障或网络中断**。系统故障期间产生的工时填报缺失，由信息中心出具故障证明后，员工统一在故障恢复后2个工作日内补录，不计入逾期。

## 5. 处罚与追责

员工逾期未填报工时（超过截止日3个工作日且未办理补录手续）的，首次予以书面提醒；当月累计逾期超过2次的，纳入当月绩效扣分，每次扣0.5分；连续3个月逾期或单月逾期超过5次的，月度绩效降一档处理。

故意虚报、篡改或代填他人工时的，视情节轻重给予警告至解除劳动合同的处分；造成绩效奖金、项目结算等经济损失的，依法追偿。项目经理审核工时存在明显失职（如对不合理工时一律放行）的，纳入管理岗位考核，扣减管理津贴。

## 6. 附则

本制度自2026年1月1日起施行，由人力资源部牵头解释，工时管理系统主管部门负责日常执行。本制度修订时，由制度责任部门发起评审，经管理层审定后发布。修订记录见制度变更日志。

# 工时审核管理办法

## 1. 适用范围

本办法适用于公司各级工时审核人员的审核行为，包括项目经理、部门主管、二级审核人（部门负责人）以及最终复核人（人力资源部）。审核对象覆盖员工日常工时、跨项目分摊工时、加班工时、补录工时、异常工时等全部工时类型。

适用场景包含：日常月度审核、季度抽查复核、年度审计、特定项目专项审核等。涉及外包人员工时审核时，参照本办法执行；涉及子公司或分公司员工的，由当地工时管理责任人按本办法执行。

## 2. 定义与术语

- **一级审核**：由员工所在项目的项目经理或直接业务上级实施的首轮审核。
- **二级审核**：由部门负责人或工时管理负责人在一级审核通过后实施的复核。
- **审核SLA**：从员工提交工时到完成所有审核动作的服务时限，通常为提交后2个工作日内一级、5个工作日内全部完成。
- **驳回**：审核人对工时记录提出异议、要求员工修改后重新提交的动作。
- **预警工时**：系统按照阈值规则（如单日超过12小时、单周超过60小时）自动标识、需要审核人重点关注的工时。

## 3. 核心规则

### 3.1 审核权限分级

项目经理拥有本项目所有工时记录的一级审核权，不得审核非本项目工时；部门负责人拥有本部门员工跨项目工时的二级复核权；人力资源部拥有全公司工时的最终复核权与抽查权。任何审核人不得对自己提交的工时进行审核。审核权限的开通、变更和回收由系统管理员根据组织架构变更在2个工作日内完成。

### 3.2 审核时限要求

一级审核应在员工提交后2个工作日内完成；超出2个工作日未完成的，系统将自动催办，连续3个工作日未审核的，工时将自动升级到部门负责人；月底集中审核期（每月1日至5日）一级审核SLA压缩到1个工作日内。所有月度工时的最终审核应在次月10日前全部完成。

### 3.3 驳回规则

审核人发现工时存在以下情况之一的，应当驳回并说明原因：项目归属错误、工时数明显与工作量不符、缺少必要任务说明、跨项目分摊比例不合理、超出预警阈值且无合理解释。驳回时必须填写驳回原因（不少于20个字），并指明需要员工修改的具体方面。员工应在收到驳回后2个工作日内修改并重新提交。

### 3.4 抽查与复核机制

人力资源部每季度对全公司工时数据进行不少于10%的抽查；对于全年累计工时排名前5%或后5%的员工，开展专项核查；对于审核通过率高于98%或驳回率高于30%的项目经理，进行管理动作回顾。复核发现问题的，按异常工时处理办法相应规则处理。

## 4. 例外情况

**情况一：审核人请假或离职**。审核人连续休假超过3个工作日或离职的，应当在请假/离职前指定代理审核人；未指定的，由系统自动按组织架构上溯到上级，由上级直接审核或指派。

**情况二：跨部门临时项目**。员工临时支援其他部门项目的，审核权由临时项目经理行使，原部门负责人享有知情权和异议权，原部门负责人在审核完成后5个工作日内可发起异议复核。

## 5. 处罚与追责

审核人对明显异常工时一律放行（如连续3次审核出现明显与工作量严重不符），视为审核失职，纳入年度管理者考核；累计放行预警工时超过10次的，扣减管理津贴并暂停审核权限。审核人故意拖延审核或刁难员工的，员工可向人力资源部投诉，经查实将进行通报和绩效扣减。

## 6. 附则

本办法自2026年1月1日起施行，由人力资源部联合工时管理系统主管部门负责解释，部门负责人对本办法在本部门的执行情况承担管理责任。本办法每2年至少修订1次，遇重大组织变更随时启动修订。

# 跨项目工时分摊规则

## 1. 适用范围

本规则适用于同时参与2个或以上项目的员工的工时分摊行为，包含全职抽调、兼项支持、临时支援、内部顾问等多种参与形式。所有需要将单日或单周工时按比例归属到不同项目的员工，必须按本规则执行分摊。

适用对象覆盖技术研发岗、产品岗、设计岗、测试岗、项目管理岗、运营岗等参与多项目的员工。仅参与一个项目（含主业务+少量内部会议）的员工不适用本规则，按单项目工时填报即可。

## 2. 定义与术语

- **主项目**：员工当前承担工作量比例最高的项目，原则上工作量占比≥50%。
- **兼项**：员工除主项目外参与的其他项目，单项工作量占比通常在10%~40%之间。
- **分摊比例**：员工将每日或每周工时按一定百分比归属到各项目的比例，所有项目分摊总和必须等于100%。
- **分摊周期**：分摊比例的最小适用周期，原则上为1周（周一至周日），允许按月调整。
- **项目权重**：项目本身的优先级权重，由项目经理与员工的部门负责人共同确认，不直接决定分摊比例但作为参考。

## 3. 核心规则

### 3.1 分摊比例确定

员工同时参与多个项目的，应在每周第一个工作日12:00前，与所有相关项目经理协商确定本周分摊比例。比例最小颗粒度为10%，每个项目的分摊比例不得低于10%。比例总和必须严格等于100%；若员工未及时确定比例，系统按上一周的分摊比例自动延续。

### 3.2 主项目认定

员工的主项目应满足以下条件之一：单一项目工作量占比≥50%、合同或抽调单中明确指定为主项目、所属部门负责人书面确认。一个员工同一周期内只能有1个主项目，主项目变更需提前3个工作日向涉及的所有项目经理同步并经员工部门负责人确认。

### 3.3 工时填报与分摊一致性

员工每日工时录入时，应按照已确定的分摊比例将当日工时分配到各项目。允许日内偏差±10%，但单周累计偏差超过15%的，需要在周末汇总时进行调平，调平方式为：从超出比例的项目工时中扣减，并加到不足比例的项目；不可通过虚报或漏报达到调平。

### 3.4 跨部门项目的特殊规则

涉及跨部门支援的工时，员工部门负责人对工时合规性承担最终责任，项目经理对工时真实性承担直接责任。当员工同时支援2个以上跨部门项目时，分摊总比例中给予跨部门项目部分不得超过60%；超过此阈值需上报部门负责人和项目PMO评审。

## 4. 例外情况

**情况一：临时紧急项目占用**。因突发故障、紧急客户支持等原因临时被抽调到其他项目超过4小时的，可在事后2个工作日内调整本日的分摊比例，无需提前协商。

**情况二：项目交付前冲刺期**。项目进入交付前2周冲刺期的，员工经主项目经理同意，可在该2周内将主项目分摊比例临时提升至80%以上，但需通知所有兼项项目经理。

## 5. 处罚与追责

员工长期未按分摊比例填报（连续3周偏差超过15%），项目经理可发起核查；核查发现故意倾斜或虚报的，按异常工时处理。项目经理之间因分摊比例发生争议且不能自行解决的，由PMO在3个工作日内介入裁决；不接受PMO裁决的，可向部门负责人或最高决策层升级。

## 6. 附则

本规则自2026年1月1日起施行，由PMO联合人力资源部负责解释。涉及多部门重大调整的，须经各部门负责人共同确认。本规则与工时填报管理制度、跨部门工时协调流程配合使用，遇冲突时以本规则为准。

# 工时类型分类标准

## 1. 适用范围

本标准适用于公司全体员工在工时管理系统中对工时进行分类录入的全部场景，作为系统下拉菜单"工时类型"字段的统一定义来源。任何新增、合并、删除工时类型的，必须先经过本标准修订发布，再在系统中生效。

适用部门覆盖研发、测试、运维、产品、设计、市场、销售、人力、财务、行政等全部职能部门。涉及外包及临时人员的工时分类，原则上参照本标准执行；与外包合同约定不同的，以合同约定优先。

## 2. 定义与术语

- **工时类型**：对一段工时所属工作性质的描述维度，独立于项目维度存在；用于统计该员工或该部门在某类活动上的投入。
- **直接工时**：直接产生客户交付物或外部价值的工时，如研发编码、测试用例执行等。
- **间接工时**：支持性、管理性、培训性等不直接产生交付物，但对组织正常运转必要的工时。
- **共享工时**：跨多个项目共享、不属于任何单一项目的工时（如全员培训、部门会议）。
- **可计费工时**：可向外部客户计费或在内部成本核算时分摊到具体项目预算的工时。

## 3. 核心规则

### 3.1 直接工时分类

直接工时包含以下7个子类，每类有专属编码：研发编码（D01）、需求调研（D02）、产品设计（D03）、UI/视觉设计（D04）、测试执行（D05）、客户实施（D06）、技术支持（D07）。员工录入时必须选择最贴合实际工作内容的子类，不得用上一级类别（D00）兜底。

### 3.2 间接工时分类

间接工时包含以下6个子类：内部会议（I01）、培训学习（I02）、文档撰写（I03）、技术调研（I04）、招投标支持（I05）、流程优化（I06）。其中内部会议每周累计上限不得超过8小时，超过部分应转为对应项目工时或备注例外原因。培训学习每月累计上限24小时，超过需所属部门负责人审批。

### 3.3 共享工时与非项目工时

共享工时包括：全员大会、团建活动、企业文化活动、年度规划会议等。共享工时统一计入"非项目工时"类别下的相应任务，不占用项目预算。共享工时单月累计原则上不超过16小时，超过部分须人力资源部备案。

### 3.4 可计费工时识别

可计费工时由项目经理在项目立项时与财务部门商定后，在系统中标记。员工在录入时无需自行判断是否可计费，由系统根据项目维度自动识别。年度审计中可计费工时占比的目标值由经营管理层每年发布。

## 4. 例外情况

**情况一：复合性工作**。一段工时同时涉及多种类型（如边写代码边开会），按照主导活动归类，主导活动占比应不低于60%；分歧时按时长更长的活动归类。

**情况二：新业务工时**。出现现有分类无法覆盖的新型工作（如新业务孵化、合规整改专项），先归入"待分类"类别，由人力资源部和PMO在2个月内补充分类。

## 5. 处罚与追责

员工故意将间接工时归入直接工时（虚增可计费工时）的，按虚报工时处理；累计3次以上的，纳入诚信档案。项目经理对本项目下工时类型分布有明显异常（如间接工时占比超过50%）未及时发现的，纳入管理者考核。

## 6. 附则

本标准自2026年1月1日起施行，由PMO负责解释和定期评审。每个财年末（12月）发起一次全面回顾，对类型增删进行集中处理。重大业务调整时，可在财年中期发起临时修订。

# 异常工时处理办法

## 1. 适用范围

本办法适用于公司全部员工和审核人在工时管理过程中出现的各类异常情况的认定与处理，包含但不限于：超时工时、漏填工时、重复填报、虚报工时、代填代审等。处理对象覆盖一线员工、项目经理、部门负责人和系统管理员。

适用场景包含日常监控、月度核对、季度审计、年度合规检查等多种触发情境。涉及外部审计或法律调查相关的工时异常，由本办法配合公司合规及法律部门联合处理。

## 2. 定义与术语

- **超时工时**：员工单日实际填报工时超过12小时，或单周累计超过60小时的情况。
- **漏填工时**：员工在工作发生日后超过3个自然日仍未录入对应工时。
- **重复填报**：同一时段、同一项目、同一任务下出现2条及以上工时记录的情况。
- **虚报工时**：员工故意填报与实际工作不符的工时，包含虚增、虚减或挪用至其他项目。
- **异常等级**：根据问题性质和影响范围划分的处理优先级，分为A（严重）、B（一般）、C（轻微）3级。

## 3. 核心规则

### 3.1 异常识别与分级

A级异常：故意虚报、篡改、代填他人工时；月度逾期超过5次；连续3周超时填报。B级异常：单次超时超过预警阈值且无合理说明；连续2次漏填；分摊比例偏差累计超过20%。C级异常：偶发漏填或晚填；非故意的重复填报；填报项目归属错误。系统对异常自动打标签并推送给对应审核人，审核人2个工作日内确认等级。

### 3.2 处理时限

A级异常应在识别后1个工作日内启动专项核查，5个工作日内出处理结论；B级异常在3个工作日内由审核人或部门负责人现场处理；C级异常由员工在2个工作日内自行更正即可，无需上报。逾期未处理的异常，自动升级一级。

### 3.3 处理动作清单

C级异常：员工自行更正、审核人确认、记录在案。B级异常：员工书面说明、审核人复核、纳入员工或团队的月度提醒。A级异常：人力资源部介入调查、可能涉及绩效扣分、警告处分、严重者解除劳动合同；造成经济损失的依法追偿。

### 3.4 申诉与复核

员工对异常认定有异议的，可在收到通知后5个工作日内向审核人和部门负责人书面申诉。申诉期间该笔工时进入"申诉中"状态，不得直接处罚。申诉处理时限不超过10个工作日；员工对申诉结果仍不服的，可继续向人力资源部投诉。

## 4. 例外情况

**情况一：因系统问题导致的异常**。经信息中心确认是系统故障导致的重复、漏填、超时等异常，不计入员工记录，直接由系统管理员后台修正。

**情况二：组织变更引发的批量异常**。因部门合并、项目转隶导致大批员工工时归属错误的，由人力资源部联合PMO批量处理，处理过程不影响员工绩效。

## 5. 处罚与追责

员工出现A级异常的，依据情节轻重处以警告、记过、降级、解除劳动合同等处分；造成项目经济损失的，按公司财务管理制度依法追偿。审核人对A级异常未及时上报或包庇的，与员工同等问责。系统管理员擅自修改工时数据的，按违反信息安全制度处理。

## 6. 附则

本办法自2026年1月1日起施行，由人力资源部联合PMO负责解释。本办法与工时审核管理办法配套使用；遇冲突时以本办法为准。每年至少修订1次。

# 项目经理工时管理职责

## 1. 适用范围

本规定适用于公司全部正式立项的项目的项目经理，含核心业务项目、内部支持项目、研发预研项目等所有类型项目。对于多人联合担任项目经理的项目，由项目章程指定的"主项目经理"承担本规定下的全部责任，其他项目经理承担辅助责任。

也适用于项目经理代理人（项目经理休假或长期出差期间的临时代理者），代理期间代理人享有相同权利并承担相同责任。涉及子公司项目的，由子公司项目经理参照本规定执行。

## 2. 定义与术语

- **项目经理**：负责一个项目的整体计划、执行、交付和团队管理的责任人，简称PM。
- **工时审核责任**：项目经理对本项目所有成员工时记录的真实性、合理性、合规性承担首要责任。
- **工时督促责任**：项目经理负责督促本项目成员按时完成填报、避免逾期。
- **工时统计责任**：项目经理需在月度、季度、项目阶段结束时对工时进行汇总分析，向上汇报。
- **绩效关联度**：工时管理工作对项目经理本人绩效的关联系数，原则上不低于15%。

## 3. 核心规则

### 3.1 审核责任

项目经理应在每次员工提交工时后2个工作日内完成审核；月度集中审核期（每月1日至5日）SLA压缩到1个工作日。审核率（已审核工时数/总提交工时数）月度不得低于98%。审核驳回需明确驳回原因和修改建议，不得无理由驳回。

### 3.2 督促责任

项目经理应在每月3日和5日通过企业微信、OA或工时系统提醒功能，至少2次提醒未完成填报的成员；对于连续2次逾期的成员，应当面或视频沟通确认原因。本项目月度填报完成率（按时填报人数/项目总人数）不得低于95%；连续2个月低于该指标的，纳入项目经理绩效。

### 3.3 统计与汇报责任

项目经理需在每月10日前向部门负责人和PMO提交本项目上月工时分析报告，含：总工时、按成员分布、按工时类型分布、超时与异常情况、与计划的偏差。每个项目阶段（里程碑）结束后5个工作日内提交阶段性工时复盘报告。

### 3.4 数据保密责任

项目经理对项目工时数据负有保密义务，不得对外披露成员个体工时；不得将工时数据用于非项目管理目的。如有外部审计或客户需求，须经部门负责人批准后脱敏提供。

## 4. 例外情况

**情况一：项目经理本人离职或长期休假**。项目经理预计离开岗位超过5个工作日的，应提前指定代理人，并在系统中正式委托权限；未指定的，由部门负责人临时接管。

**情况二：跨部门联合项目**。多个部门联合开展的项目，主项目经理承担本规定全部职责，副项目经理仅承担本部门成员的工时督促责任，审核权由主项目经理或其指派人行使。

## 5. 处罚与追责

项目经理审核率连续2个月低于95%、填报完成率连续2个月低于90%的，扣减管理津贴并约谈；审核存在明显失职导致虚报、超时未发现的，按异常工时处理办法相应规则联动追责。项目经理擅自修改成员工时或泄露工时数据的，依照公司相关制度处理。

## 6. 附则

本规定自2026年1月1日起施行，由PMO联合人力资源部解释。本规定与工时审核管理办法、异常工时处理办法配套使用；新增项目经理须在任命后10个工作日内完成本规定的学习与签字确认。

# 月度工时填报操作流程

## 1. 流程目的

帮助员工在每月最后一个工作日至次月5日的窗口期内，规范、完整、及时地完成本月所有工时的录入、自查和提交，避免因漏填、错填或逾期带来的绩效影响和审核返工。本流程也为新员工和返岗员工提供月度工时填报的可执行操作指南。

## 2. 适用场景

- 每月月底员工对当月日常工时的最终汇总与提交
- 因出差、休假、培训等原因未实时填报的工时回溯录入
- 月度切换期间的跨月工时补录（最后一周工时跨过月底的情形）
- 新入职或返岗员工的首次月度填报

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 员工 | 按时完成本人当月全部工时的录入、自查和提交 |
| 项目经理 | 在员工提交后2个工作日内完成审核，对异常项及时沟通 |
| 部门负责人 | 对本部门员工的填报进度进行月度督导，对预警员工进行约谈 |
| 系统管理员 | 保证系统在月底高峰期正常运行，处理紧急导入导出请求 |

## 4. 操作步骤

### Step 1: 月底前自查日清

- 操作人：员工
- 输入：当月已填工时记录、项目任务清单
- 动作：每月最后3个工作日内，登录工时系统进入"我的工时"页签，按周回顾每日工时是否完整；对照日历找出漏填日期，缺漏部分立即补录。
- 输出：当月所有工作日均有工时记录的状态
- 时限：每月最后3个工作日内完成

### Step 2: 关联项目与任务复核

- 操作人：员工
- 输入：项目分摊比例、任务清单
- 动作：检查每条工时是否关联了正确的项目和任务，特别注意月初月末跨项目分摊；对存在歧义的项目咨询对应项目经理。
- 输出：项目和任务关联无误的工时记录
- 时限：30分钟内完成单月复核

### Step 3: 异常项预审

- 操作人：员工
- 输入：系统弹出的异常提醒（如单日超过12小时、单周超过60小时）
- 动作：对每条异常项填写详细备注，备注不少于30字；如果异常源于实际加班，应同时提交加班审批；如果是误录，立即修改。
- 输出：所有异常项均已说明或修正
- 时限：1个工作日内完成

### Step 4: 月度汇总并提交

- 操作人：员工
- 输入：自查通过的当月工时记录
- 动作：在"月度提交"页签点击"汇总预览"，确认总工时、各项目分布、各工时类型分布与个人记忆一致；点击"提交月度工时"。
- 输出：进入"待审核"状态的月度工时汇总
- 时限：每月5日24:00前完成

### Step 5: 跟踪审核状态

- 操作人：员工
- 输入：审核进度通知
- 动作：每日登录系统查看审核状态；如收到驳回通知，2个工作日内修改并重新提交；如审核长期未推进，主动联系项目经理。
- 输出：所有工时进入"已审核通过"状态
- 时限：每月10日前全部完成审核

### Step 6: 异议申诉（可选）

- 操作人：员工
- 输入：被驳回或被异常标记的工时
- 动作：如认为审核存在误判，按工时申诉与补录流程提交申诉；申诉期间不影响其他正常工时。
- 输出：申诉处理完成的工时记录
- 时限：收到驳回后5个工作日内发起

## 5. 异常处理

**异常一：月底系统拥堵无法提交**。每月3日至5日系统压力较大，遇到无法提交时不要反复刷新；可在企业微信工时管理群中反馈，信息中心会广播状态；遇严重故障导致整体不可用的，等故障公告后再操作，逾期不计责任。

**异常二：项目经理未在SLA内审核**。员工在提交后第3个工作日仍未见审核状态变更的，可主动通过企业微信联系项目经理；连续2个工作日仍无回应，可向部门负责人或PMO反映。

**异常三：跨月工时归属难以判断**。月初跨月加班、月末项目交付期跨月等情况，工时按实际工作发生日归属；同一段连续工作跨午夜的，按实际起止时间分别归属到对应日期。

## 6. 时效要求

| 节点 | 时限 |
|------|------|
| 自查日清 | 每月最后3个工作日内 |
| 月度提交 | 次月5日24:00前 |
| 一级审核完成 | 次月7日前 |
| 二级审核完成 | 次月10日前 |
| 申诉受理 | 提交申诉后10个工作日内出结果 |

## 7. 相关表单与系统

- 工时管理系统（核心系统）
- 工时月度汇总报表（系统自动生成）
- 加班申请单（涉及加班工时时关联提交）
- 工时申诉单（异议申诉时使用）
- 企业微信工时管理通知群（动态广播）

# 工时审核 SOP

## 1. 流程目的

为项目经理、部门负责人等审核人提供标准化、可重复执行的工时审核流程，确保审核动作及时、准确、留痕，并能有效识别异常工时、合理处理跨项目分摊和加班场景。最终目标是提升整体工时数据质量，使审核SLA控制在2个工作日内、月度审核完成率达到100%。

## 2. 适用场景

- 项目经理对本项目员工的日常工时审核
- 部门负责人对跨项目工时的二级复核
- 月度集中审核期（每月1日至5日）的高频审核
- 异常工时的专项核查
- 季度抽查与年度审计

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 项目经理 | 一级审核责任人，2个工作日内完成审核 |
| 部门负责人 | 二级审核责任人，处理跨项目和疑难工时 |
| PMO | 提供分摊比例、项目权重等参考数据 |
| 系统管理员 | 维护审核权限、处理系统异常导致的审核问题 |
| 人力资源部 | 组织季度抽查与年度审计 |

## 4. 操作步骤

### Step 1: 进入审核工作台

- 操作人：项目经理
- 输入：员工提交的待审核工时
- 动作：登录工时系统，进入"审核工作台"，默认按提交时间倒序展示；可按员工、项目、日期等条件筛选；勾选"仅显示异常项"快速定位预警工时。
- 输出：当前待审核工时列表
- 时限：每日上午9:30和下午16:30两个固定时段查看，月底每日多次查看

### Step 2: 单条工时核对

- 操作人：项目经理
- 输入：单条工时记录（含日期、项目、任务、工时数、备注）
- 动作：核对工时数与项目实际进度是否匹配；任务描述是否清晰；分摊比例是否符合本周确定的比例；是否需要补充加班审批等关联信息。
- 输出：判定结果（通过/驳回/转复核）
- 时限：单条审核时间不超过3分钟

### Step 3: 批量审核与异常单独处理

- 操作人：项目经理
- 输入：常规工时与异常工时
- 动作：对常规工时使用"批量通过"功能，提升效率；对异常项（系统标红）逐条查看并单独处理；对超时类异常要核对加班审批；对分摊偏差大的，与员工沟通调平。
- 输出：常规工时已批量通过，异常项已单独标注处理
- 时限：日常每天15分钟内，月底每天30-60分钟

### Step 4: 驳回与备注

- 操作人：项目经理
- 输入：需要驳回的工时
- 动作：在驳回页面填写不少于20字的驳回原因，明确指出问题（如"项目归属错误，应该在A项目而非B项目"）；选择驳回类型（项目错误/分摊偏差/任务缺失/其他）；提交后系统自动通知员工。
- 输出：员工收到驳回通知和具体原因
- 时限：驳回后立即生效

### Step 5: 跨部门或疑难工时上转

- 操作人：项目经理
- 输入：本人无法判断的工时（涉及其他部门、需高层裁决等）
- 动作：在审核界面选择"上转"，附本人初步意见和疑问点；系统自动转给部门负责人或PMO。
- 输出：进入"复核中"状态的工时
- 时限：识别后1个工作日内上转

### Step 6: 二级复核（部门负责人）

- 操作人：部门负责人
- 输入：被项目经理上转或系统抽样选中的工时
- 动作：核对一级审核意见的合理性；对跨项目分摊的争议进行裁决；对疑难工时与员工和项目经理三方沟通后定案。
- 输出：终审通过或驳回的工时
- 时限：3个工作日内完成

## 5. 异常处理

**异常一：员工长时间不修改被驳回工时**。审核人发起驳回后，员工连续2个工作日未修改的，审核人可通过系统再次催办；催办仍无回应的，转部门负责人协调。

**异常二：审核人对工时合理性判断把握不准**。审核人对工时数与工作量是否匹配存疑时，可在系统中调阅员工本月趋势、同岗位同项目同事对比数据；仍无法判断的，转PMO评估。

**异常三：审核SLA即将超时**。系统在审核截止前6小时和2小时分别发送提醒；审核人确实无法在SLA内完成的，应在系统中说明原因（出差、紧急事件等），并指定代理人接管。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 一级审核常规月份 | 提交后2个工作日内 |
| 一级审核月度集中期 | 提交后1个工作日内 |
| 二级复核 | 上转后3个工作日内 |
| 审核完成率（月度） | ≥98% |
| 月度审核终结时间 | 次月10日前 |

## 7. 相关表单与系统

- 工时管理系统（审核工作台）
- 工时驳回单（系统自动生成）
- 工时复核单（二级复核时使用）
- 加班审批单（关联查询）
- PMO项目权重表（参考用）

# 工时申诉与补录流程

## 1. 流程目的

为员工提供对工时审核结果有异议或因合理原因错过填报截止时间时的标准化处理路径，保障员工的工时数据真实记录权和申诉权，同时通过流程约束减少滥用申诉、随意补录的情况。最终使每月申诉处理时长不超过10个工作日，补录通过率维持在合理范围内。

## 2. 适用场景

- 工时被项目经理驳回，员工认为驳回不合理
- 工时被系统标记为异常，员工有合理解释
- 因出差、休假、紧急事件等错过填报截止时间需要补录
- 系统故障期间未能正常填报需要事后补录
- 跨月跨项目工时归属争议的更正请求

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 员工 | 发起申诉或补录，提供必要证据 |
| 项目经理 | 一级处理人，对申诉或补录初步审核 |
| 部门负责人 | 二级处理人，对项目经理裁决有争议时复核 |
| 人力资源部 | 终审责任人，对申诉或补录最终结论负责 |
| 信息中心 | 出具系统故障证明（涉及系统故障时） |

## 4. 操作步骤

### Step 1: 选择申诉或补录路径

- 操作人：员工
- 输入：被驳回工时或未填报工时的具体信息
- 动作：登录系统进入"申诉与补录"模块；根据情形选择"申诉"或"补录"；申诉用于对已审核结果的异议，补录用于追加录入未填工时。
- 输出：进入相应表单填写页面
- 时限：被驳回后5个工作日内 / 错过截止后10个工作日内

### Step 2: 填写表单与上传证据

- 操作人：员工
- 输入：必要的证据材料
- 动作：详细填写申诉/补录原因（不少于100字）；上传相关证据（如出差行程截图、医院证明、系统故障公告链接等）；指定关联的项目和任务。
- 输出：完整的申诉/补录单
- 时限：30分钟内完成填写

### Step 3: 提交并等待项目经理审核

- 操作人：员工 → 项目经理
- 输入：申诉/补录单
- 动作：员工提交后系统自动转项目经理；项目经理收到通知后查阅证据，与员工沟通核实；做出"同意/驳回/转复核"的决定。
- 输出：项目经理的初步意见
- 时限：项目经理3个工作日内处理

### Step 4: 部门负责人复核（必要时）

- 操作人：部门负责人
- 输入：项目经理转交的申诉/补录单
- 动作：审视项目经理意见的合理性；可与员工面谈或电话核实；做出"同意/驳回"的决定；对争议较大的，可上转人力资源部。
- 输出：部门负责人复核意见
- 时限：5个工作日内处理

### Step 5: 人力资源部终审（必要时）

- 操作人：人力资源部审核员
- 输入：部门负责人转交或员工二次申诉的单据
- 动作：综合评估证据真实性、政策合规性；必要时召集三方会议（员工、项目经理、HR）；给出最终结论。
- 输出：终审决定（同意/部分同意/驳回）
- 时限：10个工作日内出结论

### Step 6: 结果落地与系统更新

- 操作人：系统管理员或员工
- 输入：终审通过的工时调整指令
- 动作：员工在系统中按结论修改工时；系统管理员核对修改是否符合结论；记录处理日志归档。
- 输出：已生效的最终工时数据
- 时限：终审通过后2个工作日内完成

## 5. 异常处理

**异常一：补录金额超过当月总工时20%**。当员工单次补录超过20小时或当月累计补录超过当月正常工时20%时，自动转部门负责人审批，且不允许员工自主修改。

**异常二：申诉过程中工时数据涉及绩效计算**。如申诉处理周期跨过绩效结算节点，先按现有数据计算绩效，最终结论与原结论不同的，下个绩效周期补差或扣回。

**异常三：申诉被驳回但员工仍不服**。员工对终审结论仍有异议的，可向公司工会或更高层级管理者反映，但同一事项一般只受理一次复议。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 申诉发起截止 | 收到驳回后5个工作日内 |
| 补录发起截止 | 错过截止后10个工作日内 |
| 项目经理初审 | 3个工作日内 |
| 部门负责人复核 | 5个工作日内 |
| 人力资源部终审 | 10个工作日内 |
| 整体闭环时长 | 不超过20个工作日 |

## 7. 相关表单与系统

- 工时申诉单
- 工时补录单
- 系统故障证明（信息中心出具）
- 出差/请假证明（关联HR系统）
- 工时管理系统的"申诉与补录"模块
- 处理日志归档库

# 工时报表导出流程

## 1. 流程目的

为项目经理、部门负责人、HR等需要分析工时数据的角色提供规范的报表导出操作指引，覆盖按项目、按员工、按时间段、按工时类型等多种维度，并明确数据安全和保密要求。目标是使常规导出操作单次不超过5分钟、月度报表准确率达到99%以上。

## 2. 适用场景

- 项目经理向客户或PMO汇报项目工时投入
- 部门负责人开展月度/季度工时分析
- 人力资源部年度工时审计抽查
- 财务部门为成本分摊与项目核算导出工时数据
- 项目结项时的工时数据归档

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 项目经理 | 导出本项目工时报表，对外披露需脱敏 |
| 部门负责人 | 导出本部门工时报表，重点分析人均工时与项目分布 |
| HR | 导出全公司工时报表，做合规分析 |
| 财务 | 导出可计费工时报表，用于成本核算 |
| 系统管理员 | 维护报表模板，处理导出权限申请 |

## 4. 操作步骤

### Step 1: 确认导出权限

- 操作人：导出申请人
- 输入：需要导出的数据范围
- 动作：登录工时系统，查看"我的报表权限"；权限不足的，向系统管理员或部门负责人申请；导出范围超过本部门的，需要HR授权。
- 输出：可用导出范围确认
- 时限：当日完成权限自查

### Step 2: 选择报表模板

- 操作人：导出申请人
- 输入：业务用途（汇报/审计/核算/归档）
- 动作：进入"报表中心"，根据用途选择对应模板：项目工时月报、员工工时分析、可计费工时表、跨部门工时表等共15种内置模板；不满足需求的，使用"自定义模板"功能。
- 输出：已选定的报表模板
- 时限：5分钟内完成模板选择

### Step 3: 设置筛选条件

- 操作人：导出申请人
- 输入：维度参数（时间、项目、部门、员工、工时类型）
- 动作：填写起止日期（最长支持3年范围）；勾选项目、部门或员工；选择工时类型；高级筛选支持工时数阈值、关键字匹配等。
- 输出：筛选条件已锁定
- 时限：5分钟内完成

### Step 4: 预览数据并校验

- 操作人：导出申请人
- 输入：当前筛选条件
- 动作：点击"预览"，查看前100条数据是否符合预期；核对总工时数、人数、项目数与预期是否一致；不一致时调整筛选条件。
- 输出：预览数据通过校验
- 时限：3分钟内完成

### Step 5: 选择导出格式与执行

- 操作人：导出申请人
- 输入：报表用途
- 动作：选择导出格式（Excel xlsx / CSV / PDF）；勾选是否包含图表；点击"开始导出"；大数据量（超过10万行）任务进入后台队列，完成后通过站内消息通知。
- 输出：本地下载到的报表文件
- 时限：常规导出实时完成；大数据量导出在30分钟内完成

### Step 6: 文件加密与分发

- 操作人：导出申请人
- 输入：导出的报表文件
- 动作：涉及对外披露的报表必须使用WinRAR/7-Zip加密压缩，密码通过其他渠道告知接收方；涉及成员个人工时的，需脱敏（隐去姓名后4位、工号中段）；通过企业邮件或企业微信安全文件传输。
- 输出：加密后的报表文件
- 时限：导出后立即处理

## 5. 异常处理

**异常一：导出的报表数据与系统看到的不一致**。可能因为筛选条件不同或权限范围不同；先复核筛选条件，再联系系统管理员排查时区或权限问题。

**异常二：大数据量导出失败或超时**。建议拆分导出范围（按部门或月份分批）；或在系统低峰期（如夜间）使用后台队列；连续失败的，向系统管理员开工单。

**异常三：报表外发后发现含有敏感字段**。立即通知接收方删除原文件，使用脱敏后版本重新发送；同时按公司信息安全制度上报到信息安全负责人。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 常规导出（≤1万行） | 3分钟内完成 |
| 中量导出（1-10万行） | 10分钟内完成 |
| 大量导出（>10万行） | 30分钟内完成 |
| 异常工单处理 | 1个工作日内响应 |

## 7. 相关表单与系统

- 工时管理系统的"报表中心"模块
- 项目工时月报模板
- 员工工时分析模板
- 可计费工时报表（财务用）
- 跨部门工时表
- 自定义报表模板
- 信息安全文件传输工具（企业IM安全文件）

# 跨部门工时协调流程

## 1. 流程目的

为多个部门联合开展项目、人员相互支援等场景下的工时管理提供标准化协调路径，确保工时归属清晰、审核责任明确、数据共享可控，并避免部门间因工时归属和分摊产生持续摩擦。目标是使跨部门工时争议在3个工作日内得到协调解决，PMO介入比例控制在5%以下。

## 2. 适用场景

- 同一员工同时为2个或以上不同部门的项目工作
- 部门A的员工被临时抽调支援部门B的紧急任务
- 跨部门联合项目（含矩阵式管理）的工时分配
- 内部技术服务（如运维支撑业务部门）的工时核算
- 跨部门培训、共享会议的工时归属

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 员工 | 按协调结果填报工时，遇争议及时上报 |
| 主项目经理 | 协调发起人，明确工时分摊建议比例 |
| 兼项项目经理 | 配合协调，对分摊比例提出意见 |
| 员工部门负责人 | 工时合规性最终责任人，对分摊有最终审定权 |
| PMO | 争议仲裁方，负责跨部门协调机制设计 |

## 4. 操作步骤

### Step 1: 协调启动

- 操作人：主项目经理或员工
- 输入：跨部门工作安排
- 动作：在跨部门工作开始前2个工作日，主项目经理主动联系兼项项目经理和员工部门负责人，发起协调；说明工作内容、预计周期、需要员工投入的比例。
- 输出：协调启动通知
- 时限：跨部门工作开始前2个工作日

### Step 2: 分摊比例初步协商

- 操作人：主项目经理 + 兼项项目经理
- 输入：项目优先级、员工能力、工作量预估
- 动作：在企业微信或会议中协商每周或每月分摊比例；遵循跨项目工时分摊规则的最低10%颗粒度要求；形成书面协商纪要。
- 输出：双方初步认可的分摊比例方案
- 时限：协调启动后2个工作日内

### Step 3: 部门负责人审定

- 操作人：员工部门负责人
- 输入：分摊比例方案
- 动作：核实方案是否符合员工本职工作要求；是否影响员工绩效结算；是否需要调整员工本部门项目分配；做出"批准/调整/拒绝"的决定。
- 输出：批准的最终分摊方案
- 时限：3个工作日内

### Step 4: 系统配置与执行

- 操作人：系统管理员
- 输入：批准的分摊方案
- 动作：在工时系统中为员工配置跨项目权限和分摊模板；员工后续填报时按模板自动分配；模板有效期内员工无需手动调整比例。
- 输出：系统中已生效的分摊配置
- 时限：批准后1个工作日内

### Step 5: 月度回顾与调整

- 操作人：主/兼项项目经理 + 员工
- 输入：上月实际工时数据
- 动作：每月初回顾上月分摊执行情况；偏差超过15%的进行原因分析；如果业务情况变化，提交分摊调整申请。
- 输出：调整后的分摊方案或保持现状的确认
- 时限：每月10日前完成上月回顾

### Step 6: 争议仲裁（必要时）

- 操作人：PMO
- 输入：双方未能协商一致的分摊争议
- 动作：召集主/兼项项目经理和员工部门负责人三方会议；基于项目权重、合同约定、员工实际投入等做出仲裁；出具仲裁结论。
- 输出：PMO仲裁书
- 时限：争议提交后3个工作日内

## 5. 异常处理

**异常一：员工同时被超过2个部门要求支援**。当员工同时支援3个以上部门时，主项目经理应汇总各方需求，向PMO提交综合协调申请；PMO评估员工承载能力后给出建议，避免员工超负荷。

**异常二：兼项项目经理拒绝接受协调结果**。兼项项目经理在协商阶段拒绝合理方案的，主项目经理可直接向PMO申请仲裁；仲裁过程中员工按主项目经理建议的方案先行填报。

**异常三：员工跨部门工作未提前协调被发现**。事后发现员工已实质性参与跨部门工作但未走协调流程的，由实际接收方部门负责人补办协调手续，所涉工时正常计入但需在月度回顾中说明。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 协调启动 | 跨部门工作开始前2个工作日 |
| 协商达成 | 2个工作日内 |
| 部门负责人审定 | 3个工作日内 |
| 系统配置生效 | 批准后1个工作日内 |
| 月度回顾 | 每月10日前 |
| PMO仲裁 | 提交后3个工作日内 |

# 工时数据归档流程

## 1. 流程目的

为公司工时数据的长期保存、合规留存、历史查询和数据安全提供规范化的归档流程。覆盖月度归档、年度归档、项目归档以及审计调阅等不同场景，明确归档介质、加密方式、保留期限和销毁条件。目标是使工时数据保留期不少于3年（合规相关数据不少于7年）、月度归档100%按时完成、归档检索响应不超过2个工作日。

## 2. 适用场景

- 月度工时审核完成后的常规归档
- 项目结项时的项目工时全量归档
- 年度结算后的年度工时归档与备份
- 离职员工工时数据的人事档案归档
- 外部审计或法务调查时的归档调阅

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| HR | 归档总责任人，负责归档计划制定与监督 |
| 系统管理员 | 执行系统层归档操作，含数据库备份与加密 |
| 信息安全负责人 | 审定归档介质和加密方式，处理调阅审批 |
| 项目经理 | 项目结项归档时配合提供完整数据 |
| 财务 | 年度结算后核对可计费工时归档准确性 |

## 4. 操作步骤

### Step 1: 归档计划制定

- 操作人：HR
- 输入：年度合规要求、组织变更情况
- 动作：每年1月制定本年度归档计划，明确月度、季度、年度归档时间表；结合监管要求确定不同类别数据的保留期限（一般工时3年、合规工时7年）。
- 输出：年度归档计划表
- 时限：每年1月15日前发布

### Step 2: 月度归档

- 操作人：系统管理员
- 输入：当月已审核完成的工时数据
- 动作：每月15日（确认上月所有工时审核完成）执行月度归档脚本；将上月工时数据同步到归档库；生成MD5校验码并存档；归档库与生产库物理隔离。
- 输出：月度归档完成确认单
- 时限：每月15日前完成

### Step 3: 项目结项归档

- 操作人：项目经理 + 系统管理员
- 输入：已结项项目的全部工时数据
- 动作：项目经理在项目结项申请中勾选"归档工时数据"；系统管理员在结项后5个工作日内将该项目全部工时（含审核日志、申诉记录）打包归档；归档文件存放在项目专属文件夹并加密。
- 输出：项目工时归档包
- 时限：项目结项后5个工作日内

### Step 4: 年度归档与备份

- 操作人：HR + 系统管理员 + 信息安全负责人
- 输入：本年度全部工时数据
- 动作：每年1月底对上一年度工时数据做全量归档；同时做异地备份（不少于2个地理位置）；备份介质类型至少包含云端和离线介质（如加密硬盘）；信息安全负责人核对备份完整性。
- 输出：年度归档与备份完成报告
- 时限：每年1月31日前完成

### Step 5: 离职员工数据归档

- 操作人：HR + 系统管理员
- 输入：离职员工工时数据
- 动作：员工离职手续完成后10个工作日内，将其全部历史工时同步到人事档案模块；保留期限按当地劳动法律最低要求执行；归档后系统中员工工时仍可被项目经理查询但不可修改。
- 输出：离职员工工时已归档的确认
- 时限：离职手续完成后10个工作日内

### Step 6: 归档调阅

- 操作人：申请方 + 信息安全负责人
- 输入：调阅申请（含理由、范围、用途）
- 动作：调阅申请通过OA提交，信息安全负责人审批；批准后系统管理员从归档库提取数据并脱敏；调阅记录留痕，调阅完成后销毁临时副本。
- 输出：批准的调阅数据
- 时限：申请后2个工作日内响应

## 5. 异常处理

**异常一：归档过程中发现数据校验失败**。系统管理员立即停止当次归档操作，回查数据库与归档库差异；若差异源于审核未结束，等待审核完成后重做；源于系统bug的，转研发处理。

**异常二：归档介质损坏或丢失**。立即启动信息安全应急预案；评估数据是否可从其他备份介质恢复；如无法恢复，按公司数据丢失事件应急处理流程上报。

**异常三：跨年度数据查询**。涉及3年以上的历史数据查询，需要从离线介质恢复；提前2个工作日提交查询计划，由系统管理员安排恢复时间窗口。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 月度归档 | 每月15日前 |
| 项目归档 | 项目结项后5个工作日内 |
| 年度归档 | 每年1月31日前 |
| 离职员工归档 | 离职后10个工作日内 |
| 归档调阅响应 | 2个工作日内 |
| 数据保留期 | 一般3年、合规7年 |

## 7. 相关表单与系统

- 年度归档计划表
- 月度归档完成确认单
- 项目工时归档包（含审核日志）
- 归档调阅申请单
- 数据销毁记录单
- 工时归档库（独立部署）
- 异地备份系统
---FILE_END---

# 工时填报常见问题

## Q1: 我每天工时必须当天填吗？最晚什么时候补？

**简答**：原则上当天填，最晚不超过工作发生日后第3个自然日；月底统一截止时间是次月5日24:00。

**详细说明**：
工时管理系统鼓励员工每日下班前完成当天工时录入，但考虑到加班晚走、临时出差等情况，给予3个自然日的"宽限期"。超过3天但仍在月内的，可以正常补录；超过当月、进入次月仍未提交的，必须在每月5日24:00截止前完成；逾期则需走补录流程。

举个具体例子：周一工作发生，最晚周四前完成填报；月末29号工作的，最晚次月1日前完成；如错过次月5日截止，则需走"工时申诉与补录流程"。

**相关制度**：工时填报管理制度.md

## Q2: 一天最多能填多少小时？超过会被驳回吗？

**简答**：单日最多24小时（实际上限），但超过12小时会被系统标红，需要备注说明并附加班审批。

**详细说明**：
系统的硬性上限是24小时（毕竟一天就24小时），但任何超过12小时的工时记录都会触发预警机制。预警的工时不是直接被驳回，而是审核人会重点关注：你需要在备注中说明超时原因（如"项目交付前夜赶进度"），并且如果超过的部分属于加班，必须提前或同时提交加班审批。

单周累计超过60小时也会触发预警；连续2周超过60小时则会推送给部门负责人单独关注。所以"加班可以但要走流程"，不要为了短期赶工长期超时。

**相关制度**：工时填报管理制度.md、加班考勤记录规则.md

## Q3: 我在多个项目上工作，怎么分摊工时？

**简答**：每周一12:00前与各项目经理协商确定分摊比例，最小颗粒度10%，总和必须等于100%。

**详细说明**：
跨项目分摊的核心是"提前协商、按比例填报"。每周第一个工作日上午，员工要主动联系所有相关项目经理，达成本周分摊比例的一致；比例最小10%（即不得出现5%、7%这种非整数倍）；总和严格等于100%。

举例：员工本周50%在A项目、30%在B项目、20%在C项目，那么每天8小时工时按4/2.4/1.6小时分配。允许日内偏差±10%（实际可以4.4/2.0/1.6），但单周累计偏差超过15%的需要在周末调平。

**相关制度**：跨项目工时分摊规则.md

## Q4: 周末加班的工时怎么填？

**简答**：周末工时和工作日一样填，但必须先有加班审批；没有审批的周末工时会被驳回。

**详细说明**：
工时系统不区分工作日还是周末，按"工作发生日"如实填报即可。但是周末工时必然涉及加班，所以必须按加班考勤记录规则提前申请；事后填报时，系统会自动校验该日期是否有审批通过的加班单。

如果是临时紧急情况来不及提前审批的，应在加班结束后2个工作日内补办审批；补办时需附详细情况说明，由部门负责人和项目经理双重确认。无审批的周末工时长期不认可、不计入加班费、不结算调休。

**相关制度**：加班考勤记录规则.md

## Q5: 我误填了工时怎么办？还能修改吗？

**简答**：未审核状态可以自行修改；已审核未月结的需要项目经理驳回后修改；月结归档后需走申诉补录流程。

**详细说明**：
工时记录的"修改窗口"分3个阶段。第一阶段（已提交但项目经理未审核）：员工可以撤回修改，无需任何审批；第二阶段（项目经理已审核但未月结）：员工需要联系项目经理发起"驳回"，员工修改后再次提交审核；第三阶段（已月结归档）：必须走"工时申诉与补录流程"，由HR和系统管理员介入。

建议养成自查习惯：每周五下班前花10分钟回顾本周工时，发现错误及时改；月底前再做一次全月自查。这样可以避免大部分进入第三阶段的麻烦。

**相关制度**：工时申诉与补录流程.md

## Q6: 谁负责审核我的工时？多久能审完？

**简答**：本项目的项目经理一级审核，2个工作日内（月底集中期1个工作日内）；超时工时可能转部门负责人复核。

**详细说明**：
工时审核的"第一责任人"是该工时所属项目的项目经理。员工同时参与多个项目的，每个项目工时由各自项目经理分别审核。一级审核SLA是2个工作日；月度集中审核期（每月1日至5日）压缩到1个工作日。

如果项目经理超过2个工作日未审核，系统会自动催办；连续3个工作日未审核的，工时会自动升级到部门负责人；这种情况员工可以主动联系项目经理或在系统中查询审核进度。

**相关制度**：工时审核管理办法.md

## Q7: 出差期间没法上系统怎么填工时？

**简答**：出差结束后5个自然日内补录；连续出差超过5个工作日的可以一次性回填。

**详细说明**：
出差是工时填报的常见例外情形。短期出差（1-3天）建议出差期间用手机端APP及时填；如果客户现场网络受限，可以在出差结束当天集中补录。长期出差（连续5个工作日以上）允许出差结束后5个自然日内一次性回填，但需要在出差申请单中预先声明"工时回填"，并每周向项目经理同步进度。

注意：出差期间的工作时间和差旅时间需要分别填报。差旅时间（飞机、高铁等）单程超过4小时的部分按4小时折算工时；超过的部分不计入工时。

**相关制度**：工时填报管理制度.md

## Q8: 系统坏了或网卡导致没填上，会被处罚吗？

**简答**：不会，但需要保留系统故障的证据（公告截图等），事后2个工作日内补录即可。

**详细说明**：
信息中心会在系统故障时通过企业微信工时管理通知群广播状态；员工应当注意保留故障公告的截图或链接。故障恢复后2个工作日内补录的工时不计入逾期，不影响绩效。

如果故障期间个人也有遗忘问题（既因为系统不可用、又因为自己忙忘了），按"故障+遗忘"叠加判断：故障部分免责，遗忘部分按C级异常自行更正。建议养成习惯：每天工作结束时随手填一下，即使系统当时不可用，自己也有记录可查。

**相关制度**：工时填报管理制度.md、异常工时处理办法.md

## Q9: 内部培训和会议怎么填？算工时吗？

**简答**：算，归入"间接工时"下的"培训学习"或"内部会议"类别；月度上限分别是24小时和32小时（每周8小时）。

**详细说明**：
培训和内部会议属于间接工时，单独计入但不计入项目工时。培训学习包括：内部讲师培训、外部线上课程、专业认证学习、新人入职培训等。内部会议包括：部门例会、跨部门协同会议、Code Review、技术分享等。

为避免会议无效占用，每周内部会议工时上限是8小时（即每月约32小时）；月度培训上限24小时；超过部分需要部门负责人特批。会议工时填报时，建议在备注里写清主题和会议号，方便审核。

**相关制度**：工时类型分类标准.md

## Q10: 已经离职的员工还能查到自己历史工时吗？

**简答**：离职后90天内可凭工号联系HR查询；超过90天后查询需提交书面申请走调阅流程。

**详细说明**：
员工离职后，工时数据从生产系统迁移到人事档案归档库。在离职后90天内，前员工可凭原工号和身份证联系HR获取个人工时报表；这是一种便利通道。超过90天的，需要按"工时数据归档流程"中的"归档调阅"步骤申请。

注意：离职后查询的工时数据仅限本人个人范围；不得查询所在项目其他成员或部门整体数据。如有特殊用途（如劳动仲裁举证），由HR根据法律要求脱敏后提供。

**相关制度**：工时数据归档流程.md

# 工时审核常见问题

## Q1: 我作为项目经理审核SLA是多久？超时会怎样？

**简答**：常规月份2个工作日内，月度集中期（每月1-5日）1个工作日内；连续超时影响管理者绩效。

**详细说明**：
工时审核SLA分两档：常规月份2个工作日，月度集中审核期（每月1-5日）1个工作日。系统会在超时前6小时和2小时分别推送提醒；超时后系统自动催办。

连续3个工作日未审核的工时会自动升级到部门负责人，意味着你的管理能力被"绕过"，会留痕在管理者考核记录中。月度审核率连续2个月低于95%、填报完成率连续2个月低于90%的，会扣减管理津贴并约谈。

**相关制度**：工时审核管理办法.md

## Q2: 如何高效批量审核大量工时记录？

**简答**：使用"批量通过"按钮处理常规工时，对系统标红的异常项单独处理；建议每天固定2个时段集中审核。

**详细说明**：
高效审核的关键是"分流处理"。系统的"审核工作台"默认按提交时间倒序展示；可以勾选"仅显示异常项"先快速过完异常项；剩下的常规工时使用"批量通过"功能。

建议养成两个习惯：固定时段审核（如每天上午9:30和下午16:30），避免审核任务积压；月度集中审核期（每月1-5日）每天多次查看，避免月底加班审。批量审核时也要快速扫一眼工时数和项目，发现明显异常再单独处理。

**相关制度**：工时审核SOP.md

## Q3: 什么情况下我应该驳回员工的工时？

**简答**：项目归属错误、工时数与工作量明显不符、缺少必要任务说明、跨项目分摊比例不合理、超出预警阈值且无解释，都应驳回。

**详细说明**：
驳回不是"刁难员工"，而是数据质量保障。常见驳回情形：
1. **项目归属错**：员工把A项目工作填到B项目，或者把项目工时填到非项目类别
2. **工时数与工作量不符**：员工填写8小时但实际只参加了一个2小时会议，又说不清其他时间做了什么
3. **任务说明过于笼统**：备注只写"代码"、"开会"，无法判断是什么内容
4. **分摊比例偏差**：员工在A项目分摊比例本周应该是50%，却填成了80%
5. **超出预警阈值无解释**：单日超过12小时或单周超过60小时却没说明加班原因

驳回时必须填写不少于20字的具体原因，让员工明白怎么修改。

**相关制度**：工时审核管理办法.md

## Q4: 我休假期间谁来审核我项目的工时？

**简答**：连续休假超过3个工作日的，应在休假前指定代理审核人；未指定的，系统自动转上级。

**详细说明**：
项目经理预计离开岗位超过3个工作日（含出差、休假、培训），应当在请假流程中指定代理审核人；指定方式：在工时系统的"权限管理"中临时授权，或在请假申请中明确写出代理人。

如果忘了指定，系统按组织架构上溯：先尝试转给部门负责人，再转给上级。这种"被动转移"会留下痕迹，频繁出现的项目经理在管理者考核中扣分。建议形成习惯：每次休假前先做"工时审核交接"。

**相关制度**：工时审核管理办法.md

## Q5: 怎么处理员工反复申诉同一个被驳回的工时？

**简答**：第一次驳回后员工可申诉一次；如有新证据可二次申诉；同一事项一般只受理一次复议。

**详细说明**：
员工对驳回有异议时，应通过"工时申诉与补录流程"提交书面申诉。审核人作为一级处理人，3个工作日内处理；员工对一级结论不服的可申请部门负责人复核。

如果员工反复就同一问题申诉、又拿不出新证据，原则上不再受理；但要确认你的驳回理由确实充分、表达清楚。建议每次驳回时附上具体改进建议（如"应该填到X项目而非Y项目，因为本周分摊方案是..."），减少误解。

**相关制度**：工时申诉与补录流程.md

## Q6: 跨部门支援的员工工时该谁审核？

**简答**：临时项目经理一级审核，原部门负责人享有知情权和异议权（5个工作日内可复核）。

**详细说明**：
员工临时支援其他部门项目时，工时审核权由临时项目经理（即接收方项目经理）行使；这是因为接收方对实际工作内容最了解。但是为了防止"借调走人头"，原部门负责人保留异议权：在审核完成后5个工作日内可发起复核。

如果原部门负责人发现接收方审核明显放水（如超时工时一律放行），可向PMO申请仲裁。建议接收方项目经理审核时多与员工原部门负责人沟通，避免事后纠纷。

**相关制度**：工时审核管理办法.md

## Q7: 怎么看出工时填报存在虚报？有什么识别技巧吗？

**简答**：关注异常模式：长期无加班却产出有限、备注千篇一律、与会议室预订系统对不上、与代码提交记录不符等。

**详细说明**：
虚报识别需要"多源数据交叉"。常见识别技巧：
1. **工时数与产出对比**：看员工本月实际产出（代码量、文档数、需求数）是否匹配工时
2. **备注质量**：长期使用"日常工作"、"项目支持"等笼统备注，可能在掩盖具体内容
3. **会议工时核验**：员工自填的会议工时与会议室预订系统、企业IM日历对照
4. **趋势异常**：员工工时突然大幅上升或下降，需要确认背景
5. **同岗位对比**：相似岗位的员工工时差异过大，需要找原因

发现可疑虚报，先与员工沟通了解情况；不能擅自标记"虚报"，应按异常工时处理办法走A级异常核查流程。

**相关制度**：异常工时处理办法.md

## Q8: 我审核错了一笔工时，已经通过了，怎么修改？

**简答**：3天内可由系统管理员后台撤回；超过3天月结前由HR审批后修改；月结后只能下期补救。

**详细说明**：
审核人发现自己审核错误（如不该通过却通过了）的处理路径：
- **3天内**：联系系统管理员，提供审核单号和修改原因，后台撤回原审核状态，员工重新提交流程
- **3-30天（未月结）**：通过"工时审核异常处理单"上报，HR审批后修改
- **已月结**：原审核记录不可改，但可以在下个月度做对应调整（如冲账或备注说明）

频繁出现审核错误的项目经理（每月超过3次），会被纳入管理能力评估；建议养成"先看异常项再批量通过"的习惯，避免误审。

**相关制度**：异常工时处理办法.md

# 工时数据查询常见问题

## Q1: 我怎么查我自己的历史工时？

**简答**：登录工时系统进入"我的工时"，可按时间、项目、工时类型筛选；最长可查近3年数据。

**详细说明**：
普通员工登录工时系统后默认进入"我的工时"页签，包含：
- 当月工时一览（含每日详情、月度汇总、按项目分布）
- 历史月份切换（可一直回溯到入职月份或近3年）
- 多维度筛选（项目、工时类型、审核状态、关键字搜索备注）

支持导出为Excel便于个人留档。3年以上历史数据需要走"归档调阅"流程，由HR协助查询。手机端APP也支持"我的工时"查询，方便出差时随时查看。

**相关制度**：工时数据归档流程.md

## Q2: 我能查到同事或下属的工时吗？什么权限？

**简答**：普通员工只能查自己；项目经理可查本项目成员；部门负责人可查本部门员工；HR可查全公司。

**详细说明**：
工时查询权限严格按角色分级：
- **员工**：仅本人工时
- **项目经理**：本项目所有成员工时（含跨部门成员的本项目部分）
- **部门负责人**：本部门员工的全部工时
- **HR**：全公司工时（含历史已离职员工）
- **PMO**：全公司项目工时（按项目维度，不直接看个体）
- **财务**：可计费工时（按预算维度）

权限不足时点查询会提示"无权限"；需要扩大权限的，向系统管理员或HR申请；申请需要明确范围、用途、时长。

**相关制度**：工时报表导出流程.md

## Q3: 怎么查项目累计工时投入？谁能看到？

**简答**：项目经理可在"项目工时"页签查看，含成员明细和总览；其他角色按权限分级查看。

**详细说明**：
项目工时查询是项目经理日常工作的重要一环。"项目工时"页签提供：
- 项目总工时（按月、季度、累计）
- 按成员分布（每个成员投入了多少小时）
- 按工时类型分布（直接工时占比、间接工时占比）
- 按里程碑分布（项目阶段性工时分布）
- 趋势图（按周/月展示工时投入趋势）

部门负责人可查本部门所有项目的概况；PMO可查全公司项目；客户经理在客户授权情况下可查本客户的项目工时。

**相关制度**：工时报表导出流程.md

## Q4: 怎么按工时类型查询？比如查"会议时间"占比

**简答**：在"工时分析"模块选择"按工时类型"维度，支持员工/项目/部门多角度切片。

**详细说明**：
工时类型分析常用于优化工作结构。具体做法：
1. 进入"工时分析"模块（部分角色才有此权限）
2. 选择维度：员工、项目或部门
3. 选择工时类型筛选：如只看"会议"、"培训"、"研发编码"
4. 选择时间范围：周、月、季度、年
5. 查看占比图和趋势图

例如想看"我团队上个月会议工时占比"，选择"按部门"+"会议工时"+"上月"，系统会展示团队总工时中会议占比，以及与公司均值的对比。这有助于识别会议过多的团队，进行优化。

**相关制度**：工时类型分类标准.md

## Q5: 我能下载工时数据到Excel吗？有什么限制？

**简答**：可以，按权限范围内导出；常规导出3分钟内完成，大于10万行自动转后台队列。

**详细说明**：
工时数据导出走"报表中心"模块。导出限制：
- **行数**：单次导出不超过50万行（项目大数据建议分批）
- **时间范围**：单次最长3年
- **频次**：单用户每日不超过20次（防止滥用）
- **格式**：xlsx / CSV / PDF
- **加密**：涉及个人敏感字段（姓名、工号）的报表，建议加密压缩后传输

需要更大量级数据的，向系统管理员申请专项导出，由后台直接生成数据库快照。

**相关制度**：工时报表导出流程.md

## Q6: 离职员工的工时还能查到吗？我作为项目经理有需要

**简答**：可以，项目经理可查离职员工在本项目的历史工时；查询权限保留3年。

**详细说明**：
项目经理在员工离职后仍可正常查询其本项目内的历史工时，无需额外申请；这是因为项目复盘、客户汇报等场景需要完整数据。但是查询有限制：
- 只能看本项目的，看不到该员工在其他项目的
- 不能修改任何数据
- 查询行为留痕（HR可审计）

3年以上离职的员工，工时已迁移到归档库；查询需要走"归档调阅"，提供查询理由和证据。

**相关制度**：工时数据归档流程.md

## Q7: 怎么查我团队某段时间的加班情况？

**简答**：在"加班分析"页签，选择部门和时间范围，可查看人均加班时长、加班高峰期、TOP员工。

**详细说明**：
加班分析是部门负责人月度健康度检查的重要工具。"加班分析"页签提供：
- 人均加班时长（与公司均值、上月对比）
- 加班高峰期（识别哪几天是密集加班日）
- TOP加班员工（持续加班的员工需要关注健康和负载）
- 加班审批通过率（识别有无未审批就加班的情况）

建议每月初做一次加班分析，识别两类风险：长期高强度加班（员工健康风险）、加班但无产出（管理风险）。

**相关制度**：加班考勤记录规则.md

## Q8: 数据查询慢怎么办？特别是月底高峰期

**简答**：月底高峰期（每月3-5日）建议错峰查询；大数据量查询使用"后台任务"模式，避免阻塞。

**详细说明**：
月底高峰期工时系统压力大，常规查询响应可能从1秒上升到5-10秒。优化建议：
1. **错峰查询**：尽量在工作时段外（如早9点前、晚6点后）做大数据量查询
2. **缩小范围**：先按部门或项目筛选，再做更细的分析
3. **后台任务**：超过10万行的查询使用"后台任务"模式，完成后通过站内消息通知
4. **报表订阅**：常用报表可订阅，系统自动定期生成，无需现场查询

如果遇到查询长时间无响应（超过30秒），刷新页面重试；持续问题向系统管理员开工单。

**相关制度**：工时报表导出流程.md

# 工时异常常见问题

## Q1: 我的工时被标"异常"是什么意思？会被处罚吗？

**简答**：异常分A/B/C三级；C级最轻仅需自行更正，A级最严涉及处分；多数员工遇到的是C级（轻微）。

**详细说明**：
工时异常并不等于处罚。系统会按问题严重程度自动打标签：
- **C级（轻微）**：偶发漏填、晚填，非故意重复填报，项目归属错误等。处理方式：员工2个工作日内自行更正即可，不上报，不影响绩效
- **B级（一般）**：单次超时无说明、连续2次漏填、分摊比例偏差累计超过20%等。处理方式：员工书面说明，审核人复核，纳入团队月度提醒
- **A级（严重）**：故意虚报、篡改、代填他人工时；连续逾期超过5次；连续3周超时填报。处理方式：HR专项核查，可能涉及绩效扣分、警告、严重者解除劳动合同

第一次遇到异常标签，先看清是哪级，按对应路径处理就好。

**相关制度**：异常工时处理办法.md

## Q2: 我没填工时被标"漏填"，怎么补救？

**简答**：3个自然日内自行补录无影响；超过当月还能在月初补录；月结后须走申诉补录流程。

**详细说明**：
漏填是最常见的C级异常。补救路径取决于时间：
- **当周内发现**：直接进系统补录，无需任何审批
- **跨周但当月内**：补录后在审核时简短说明（如"周三外出回来后忘了补"）
- **当月已过但月结前**：补录会触发提醒，项目经理审核时关注
- **月结后**：只能走"工时申诉与补录流程"，需要提供合理理由

建议设手机日历提醒，每天下班前花1分钟填工时；这种习惯远比事后补救轻松。

**相关制度**：工时申诉与补录流程.md

## Q3: 同事让我帮他填工时，可以吗？

**简答**：绝对不可以，属于代填他人工时，是A级异常，可能被解除劳动合同。

**详细说明**：
代填他人工时被定义为最严重的工时违规之一，理由：
1. 工时是绩效和薪酬结算的依据，代填等于代他人接受经济利益
2. 代填等于伪造工作记录，违反诚信原则
3. 系统存有员工的登录凭证（账号密码），代填时操作的是他人账号，存在信息安全风险

无论关系多熟、对方说"求你帮个忙"、还是"我账号借你"，都不要做。如果对方确实需要补录，让他联系自己的项目经理或走申诉补录流程；同事健康原因的，可以让HR协调。

**相关制度**：异常工时处理办法.md

## Q4: 我每天加班10小时以上被标"超时"了，会扣绩效吗？

**简答**：不会直接扣，但需要备注说明并附加班审批；多次超时无加班证明的会被关注。

**详细说明**：
超时本身不是处罚原因，"无解释的超时"才是。系统的逻辑：
- 单日超过12小时或单周超过60小时触发预警
- 你需要在备注中说明（"项目交付前赶进度"等具体原因）
- 涉及加班的工时必须有审批通过的加班单

如果你正常做了加班审批，工时记录上有正当解释，那么这只是个"提醒"而非"处罚"。但是如果你长期（连续2周）超时却没加班审批，HR会关注：要么是没走流程的违规加班（要补审批），要么是虚报工时（A级问题）。

**相关制度**：异常工时处理办法.md、加班考勤记录规则.md

## Q5: 项目经理误判我"虚报工时"，怎么自证？

**简答**：通过"工时申诉与补录流程"提交申诉，附证据（会议记录、代码提交、邮件等）；HR会综合判定。

**详细说明**：
被怀疑虚报时，先冷静收集证据：
1. **会议工时**：会议邀请截图、会议纪要、参会人员列表
2. **编码工时**：代码提交记录、PR记录、代码评审参与记录
3. **沟通工时**：企业IM聊天记录截图、邮件存档
4. **现场工作**：客户现场打卡记录、出差行程
5. **加班工时**：加班审批单

通过"工时申诉与补录流程"提交申诉，附证据；项目经理3个工作日内处理；不服可上转部门负责人和HR。在HR出结论前，工时进入"申诉中"状态，不会立即处罚。

**相关制度**：工时申诉与补录流程.md

## Q6: 重复填报是怎么算的？被标了怎么办？

**简答**：同一时段、同一项目、同一任务下出现2条以上记录就算重复；多数情况下是误操作，删除多余记录即可。

**详细说明**：
系统对"重复填报"的判定较严格：同一员工、同一日期、同一项目、同一任务下，存在2条或更多工时记录。常见原因：
1. 员工切换设备时重复提交（手机端填了一次，电脑端又填了一次）
2. 网络抖动导致重试，结果系统记了2条
3. 编辑后未删除原记录（在原记录基础上又新建了一条）

发现重复后，员工进系统选择"删除多余记录"，保留正确的那条；C级异常，自行修正即可。如果是同一项目同一任务但时间不同（如上午和下午分别填了4小时），不算重复。

**相关制度**：异常工时处理办法.md

## Q7: 系统坏了导致填错或丢数据，怎么免责？

**简答**：保留系统故障证据（公告截图、错误页面截图），事后2个工作日内补录或修正即可，不计责任。

**详细说明**：
系统故障导致的工时问题，员工不需要承担责任。但需要做好"自我举证"：
1. 故障发生时立即截屏（错误页面、网络异常提示）
2. 关注信息中心在企业微信工时管理通知群的故障公告，截图保留
3. 故障恢复后2个工作日内补录或修正异常工时
4. 在补录单备注里附故障证据

故障期间正常补录的工时，系统会自动跳过逾期判定；HR审计时会调阅故障记录，确认免责依据。

**相关制度**：工时填报管理制度.md

## Q8: 异常工时申诉成功后，已扣的绩效能补回吗？

**简答**：可以，下个绩效周期补差或冲回；月内迅速申诉成功的可能直接修正当月。

**详细说明**：
申诉是有"溯及力"的：如果你的工时异常导致了绩效或奖金扣减，申诉成功后这些经济损失会被补偿：
- **当月内申诉成功**：可直接修正当月数据，不影响后续结算
- **跨月申诉成功**：先按现有数据计算绩效，下个绩效周期补差
- **跨季度/年度**：原则上仍补，但需要走HR的"绩效追溯调整"流程，可能需要部门负责人再次确认

注意：补偿是"修正错误"而非"赔偿"，仅限于实际差额；不会因申诉过程的不便给额外补偿。

**相关制度**：工时申诉与补录流程.md

# 工时填报错误案例集

## 1. 案例背景

某互联网公司研发部有员工约80人，分属5个项目组。2025年10月，PMO在季度工时数据审计中发现多个项目组存在工时数据质量问题，包括错填、漏填、分摊比例偏差等。经逐条核查，筛选出以下3个典型案例，覆盖不同类型的常见错误。

## 2. 涉及问题

- **问题一（错填）**：员工将A项目的工时误填到B项目，导致A项目进度评估失真、B项目成本虚增
- **问题二（漏填）**：员工连续出差5天未填报工时，月底集中补录时遗漏了其中2天
- **问题三（分摊偏差）**：员工跨项目分摊比例长期与协商方案不符，偏差累计超过20%

## 3. 处理过程

### 案例一：错填项目归属

某员工同时参与"客户管理系统升级"和"内部数据分析平台"两个项目。10月15日，该员工实际全天在"客户管理系统"工作，但填报时误选了"内部数据分析平台"。项目经理A（客户管理系统）在审核时发现该员工当天工时缺失，项目经理B（数据分析平台）发现工时数与任务不匹配。项目经理A与员工沟通后确认是项目归属错误，项目经理B驳回该条工时。员工在2个工作日内更正，重新提交后通过审核。该条工时被标记为C级异常，自行更正后结案。

### 案例二：出差漏填

某员工于10月21日至25日赴客户现场出差，因客户现场网络受限且工作节奏紧凑，未能及时填报工时。10月31日该员工集中补录时，遗漏了10月23日（周三）的工时。11月3日项目经理审核时发现23日工时缺失，与员工确认后得知是补录遗漏。员工在收到驳回后2个工作日内补充了23日的工时。因员工出差申请中已预先声明"工时回填"，且出差期间每周有进度同步，最终按C级异常处理。

### 案例三：分摊比例偏差

某员工参与3个项目，协商的分摊比例为50%（A项目）、30%（B项目）、20%（C项目）。10月全月实际填报中，A项目占比仅35%、B项目占比45%、C项目占比20%。经核查，员工在B项目投入了过多精力，导致A项目工时不足。项目经理A在月度回顾中指出偏差，员工解释称"B项目临时增加需求"。经PMO介入协调，确认B项目确实临时增加了需求，但员工未提前告知项目经理A调整分摊方案。最终处理：员工在11月第一周重新协商分摊比例，10月偏差部分在11月做调平处理（从B项目调减、A项目调增），该案例被标记为B级异常，纳入团队月度提醒。

## 4. 结论与启示

1. **错填的预防**：跨项目员工应养成"填报前核对项目"的习惯；系统可增加"项目确认"二次弹窗，减少误操作
2. **漏填的预防**：出差员工应在出差申请中预先声明"工时回填"，并每天记录工作日志（即使不上系统）
3. **分摊偏差的预防**：分摊比例不是"一锤子买卖"，业务变化时应主动与项目经理沟通调整，避免事后调平
4. **审核人的价值**：项目经理的细致审核是发现问题的第一道防线，不应为了效率而草率通过
5. **沟通优先**：发现工时问题后，先与员工沟通了解情况，避免直接定性为"虚报"

- 异常工时处理办法
- 工时申诉与补录流程

# 跨项目分摊争议案例

## 1. 案例背景

某制造业企业研发部员工张某同时参与"智能仓储系统"（主项目，占比50%）和"MES生产执行系统"（兼项，占比50%）两个项目。2025年11月，"智能仓储系统"进入交付前冲刺期，项目经理A要求张某将主项目分摊比例临时提升至80%。"MES生产执行系统"项目经理B认为张某在该项目有不可替代的角色，不同意比例调整。双方协商未果，张某夹在中间无法填报，导致11月前两周工时全部积压。

## 2. 涉及问题

- **争议点一**：项目经理A是否有权单方面要求调整分摊比例？
- **争议点二**：项目经理B的反对是否合理？员工是否可以在两个项目间"选边站"？
- **争议点三**：员工张某因争议无法填报工时，责任由谁承担？
- **争议点四**：PMO在争议中的角色和裁决权限是什么？

## 3. 处理过程

张某在11月8日（第二周周一）向PMO提交仲裁申请，附项目经理A和B的书面意见。PMO在收到申请后3个工作日内召集三方会议。

PMO首先核查了相关制度依据：跨项目工时分摊规则第3.3条规定"项目交付前冲刺期，员工经主项目经理同意，可在该2周内将主项目分摊比例临时提升至80%以上，但需通知所有兼项项目经理"。PMO认为项目经理A的请求有制度依据，但"通知"不等于"协商一致"，项目经理B的反对意见也应被尊重。

PMO进一步分析了两个项目的实际情况："智能仓储系统"确实处于交付前2周冲刺期，且张某在该项目中承担核心开发角色；"MES生产执行系统"虽然也需要张某，但当前阶段主要是集成测试，可以由其他团队成员临时替代。PMO还调阅了张某过去3个月的工时数据，确认其"智能仓储系统"的投入确实低于50%，存在积压。

基于以上分析，PMO做出仲裁：11月冲刺期（2周）内张某在"智能仓储系统"的分摊比例临时调整为70%，"MES生产执行系统"调整为30%；项目经理B需在1周内安排团队成员临时接替张某在"MES生产执行系统"的工作；张某被积压的11月前两周工时在仲裁结论发布后3个工作日内补录。PMO同时建议张某的部门负责人评估张某的负载情况，避免长期跨项目导致过劳。

项目经理B对仲裁结果仍有异议，但按制度规定接受PMO裁决。张某在11月12日前完成补录，11月冲刺期按70/30比例执行，12月起恢复50/50比例。

## 4. 结论与启示

1. **制度是底线，协商是常态**：制度规定了"可以"做什么，但具体比例需要项目经理之间协商；协商不成时PMO介入
2. **员工的权益要保障**：争议期间员工无法填报工时的，不应由员工承担责任；制度应明确争议期间的填报规则
3. **PMO的裁决应基于事实**：PMO不是"和稀泥"，而是基于制度依据、项目实际情况、历史数据做出有说服力的裁决
4. **临时调整要有时间边界**：冲刺期的临时调整应有明确的起止时间，避免"临时"变"长期"
5. **部门负责人应关注员工负载**：长期跨项目员工容易过劳，部门负责人应定期评估并做人员调配

- 跨项目工时分摊规则
- 跨部门工时协调流程
- 工时填报管理制度
- 项目经理工时管理职责

# 考勤管理制度

## 1. 适用范围

本制度适用于公司全体正式员工、试用期员工和实习生。短期外包人员、临时驻场人员按合同约定执行考勤管理，不在本制度直接覆盖范围内。适用场景涵盖标准工时制员工、弹性工时制员工、综合工时制员工和轮班制员工。

本制度不适用于以下情形：高管（VP及以上）的战略性外出、董事会成员活动、外部社会活动时间。

## 2. 定义与术语

- **标准工时**：每周工作5天、每天8小时的工作安排，核心工作时段为9:00-18:00（含午休1小时）。
- **打卡**：员工通过考勤系统（指纹/人脸/手机APP）记录上下班时间的动作。
- **迟到**：员工实际到岗时间晚于规定上班时间超过5分钟。
- **早退**：员工实际离岗时间早于规定下班时间超过5分钟。
- **旷工**：员工未经请假或请假未获批准而缺勤的行为。
- **全勤**：员工在统计周期内无任何迟到、早退、旷工、请假记录的状态。

## 3. 核心规则

### 3.1 打卡规则

标准工时制员工每日须打卡2次：上班卡和下班卡。打卡地点为公司办公区域或经批准的远程办公地点。打卡时间以考勤系统服务器时间为准。员工应在上班前15分钟至上班后15分钟内完成上班打卡；下班卡应在下班后15分钟内完成。因特殊原因无法按时打卡的，应在2个工作日内提交补卡申请。

### 3.2 迟到与早退认定

迟到认定：实际到岗时间比规定上班时间晚5分钟以内不计迟到；晚5分钟至30分钟计为"一般迟到"；晚30分钟至2小时计为"严重迟到"；晚2小时以上按旷工半天处理。早退认定：实际离岗时间比规定下班时间早5分钟以内不计早退；早5分钟至30分钟计为"一般早退"；早30分钟至2小时计为"严重早退"；早2小时以上按旷工半天处理。

### 3.3 旷工认定与处理

员工未请假或请假未获批准而缺勤的，按旷工处理。旷工半天按当日工资2倍扣减；旷工1天按当日工资3倍扣减；连续旷工3天或月累计旷工5天以上的，视为严重违纪，公司有权解除劳动合同。

### 3.4 全勤奖励

员工月度全勤（无任何迟到、早退、旷工、请假记录）的，当月发放全勤奖金200元。季度全勤的，额外发放季度全勤奖金500元。年度全勤的，额外发放年度全勤奖金2000元并在年度评优中优先推荐。

## 4. 例外情况

**情况一：因公外出**。员工因公外出（客户拜访、会议、培训等）无法在公司打卡的，应在外出申请中注明，经直属上级批准后，按外出申请记录替代打卡记录。

**情况二：设备故障或网络异常**。因考勤设备故障或网络异常导致无法打卡的，应在2个工作日内向行政部报备，由行政部出具证明后按正常出勤处理。

**情况三：恶劣天气或交通管制**。因台风、暴雨、暴雪等不可抗力或交通管制导致无法按时到岗的，经公司统一通知后，当日迟到不计入考勤异常。

## 5. 处罚与追责

员工月度迟到或早退累计3次以内的，每次扣减绩效0.5分；累计4-6次的，每次扣减绩效1分；累计7次以上的，每次扣减绩效2分并通报批评。严重迟到或早退每次扣减绩效2分。员工代打卡或请他人代打卡的，视为严重违纪，一经发现给予记过处分；累计2次的，解除劳动合同。

## 6. 附则

本制度自2026年1月1日起施行，由人力资源部负责解释。各部门应在本制度发布后10个工作日内完成全员宣贯。本制度每年至少修订1次，遇重大组织变更随时启动修订。

# 打卡规则与异常认定

## 1. 适用范围

本规定适用于公司全体员工的日常考勤打卡行为，涵盖上班打卡、下班打卡、外勤打卡、远程打卡等多种打卡场景。涉及不同工时制度（标准工时、弹性工时、综合工时、轮班制）的打卡规则差异，在本规定中分别说明。

适用设备包括公司部署的考勤终端（指纹/人脸识别）、手机APP定位打卡、PC端网页打卡等。临时外包人员按合同约定执行，不适用本规定的补卡等条款。

## 2. 定义与术语

- **打卡记录**：员工通过考勤系统记录的上下班时间数据，是考勤统计的基础依据。
- **打卡缓冲区**：规定打卡时间前后允许的小幅偏差区间，在此区间内打卡不计异常。
- **打卡异常**：打卡记录缺失、时间超出正常范围、地点不符等不符合规定的情况。
- **补卡**：员工因合理原因未能正常打卡后，事后申请补录打卡记录的行为。
- **外勤打卡**：员工因公外出时，在客户现场或外出地点通过手机APP进行的打卡。
- **远程打卡**：员工经批准在家办公时，通过手机APP或PC端进行的打卡。

## 3. 核心规则

### 3.1 标准工时制打卡规则

标准工时制员工每日须完成2次打卡：上班打卡和下班打卡。核心工作时段为9:00-18:00，午休12:00-13:00不计入工作时间。打卡缓冲区：上班打卡允许范围为8:45-9:15，下班打卡允许范围为17:45-18:15。在缓冲区内打卡视为正常；超出缓冲区但在1小时内的，计为轻微异常（不扣绩效但计入记录）；超出1小时的按迟到/早退规则处理。

### 3.2 弹性工时制打卡规则

弹性工时制员工核心工作时段为10:00-16:00，在此期间必须在岗；其余时间可弹性安排。每日总工时不少于8小时。上班打卡允许范围为8:00-10:00，下班打卡允许范围为16:00-20:00。弹性工时员工不执行迟到早退处罚，但核心时段缺勤按旷工处理。

### 3.3 综合工时制打卡规则

综合工时制员工以周或月为周期统计总工时，不执行每日打卡要求。每周至少打卡3次（任意3个工作日），以证明在岗。月度总工时不少于标准工时（按当月工作日×8小时计算）。月度工时不足的，按缺勤天数折算扣减。

### 3.4 打卡地点要求

公司办公区域打卡通过考勤终端完成；外勤打卡通过手机APP定位，定位半径不超过客户地址500米；远程打卡需提前在系统中登记远程办公地址，打卡时定位偏差不超过200米。打卡地点与登记地址偏差超过规定范围的，系统标记为"地点异常"。

## 4. 例外情况

**情况一：考勤设备故障**。因考勤终端故障导致无法打卡的，员工应在2个工作日内向行政部报备，行政部出具故障证明后，员工无需补卡，按正常出勤处理。

**情况二：手机没电或丢失**。员工因手机没电、丢失或APP故障无法完成手机打卡的，应在当日通过企业微信或电话告知直属上级，并在2个工作日内补办补卡手续。

**情况三：跨时区出差**。员工出差至境外或西部时区的，按当地时间打卡，系统自动按出差申请中的时区设置换算。

## 5. 处罚与追责

员工连续3个工作日未打卡且无补卡记录的，按旷工处理。员工故意在错误地点打卡（如让同事在公司打卡而自己在家）的，视为严重违纪，一经发现给予记过处分；累计2次的，解除劳动合同。员工利用技术手段伪造打卡记录的（如虚拟定位、代打卡APP），按信息安全违规处理，严重者追究法律责任。

## 6. 附则

本规定自2026年1月1日起施行，由人力资源部联合行政部负责解释。本规定与考勤管理制度配套使用；遇冲突时以本规定为准。考勤系统升级或规则调整时，提前5个工作日通知全员。

# 外勤与远程办公考勤规则

## 1. 适用范围

本规则适用于员工因公外出（客户拜访、现场支持、会议等）和经批准在家远程办公的考勤管理。涵盖短期外勤（单日）、长期外派（连续5个工作日以上）、临时远程办公（单日）和周期性远程办公（固定每周若干天）等多种场景。

适用对象为公司全体正式员工；试用期员工申请远程办公需经部门负责人和HR双重审批。涉及子公司或分公司的外勤/远程办公，由当地考勤管理责任人参照本规则执行。

## 2. 定义与术语

- **外勤**：员工离开公司办公区域，前往客户现场、合作伙伴处或其他外部地点执行工作任务的行为。
- **远程办公**：员工经批准在家或其他非公司办公地点完成工作任务的行为。
- **外勤打卡**：员工在外勤地点通过手机APP进行的定位打卡。
- **远程打卡**：员工在远程办公地点通过手机APP或PC端进行的打卡。
- **外勤审批**：员工因公外出前，在系统中提交的包含外出时间、地点、事由的审批单。
- **远程办公审批**：员工申请远程办公前，在系统中提交的包含远程办公时间、原因、工作安排的审批单。

## 3. 核心规则

### 3.1 外勤考勤规则

员工因公外出前须提交外勤审批，审批通过后方可外出。外勤期间每日须完成2次打卡：出发打卡（离开公司时）和到达打卡（到达外勤地点时）；如外勤地点为公司外部，还需完成外勤打卡（在外勤地点的打卡）。外勤打卡通过手机APP定位完成，定位半径不超过外勤地点500米。单次外勤超过4小时的，须在系统中填写外勤工作日志（不少于50字）。

### 3.2 远程办公考勤规则

员工申请远程办公须提前1个工作日提交审批，审批通过后方可远程办公。远程办公期间每日须完成2次打卡：上班打卡和下班打卡，通过手机APP或PC端完成。远程打卡地址须与审批中登记的地址一致，偏差不超过200米。远程办公期间员工须保持企业IM在线，响应时间不超过30分钟。远程办公单日不得超过8小时，月度累计远程办公天数不得超过当月工作日总数的40%。

### 3.3 外勤与工时的关联

外勤期间的差旅时间（交通时间）按以下规则折算：单程交通时间不超过4小时的，按实际时间折算工时；单程超过4小时的，按4小时折算。外勤期间的工作时间按实际工作内容填报工时，与常规工时填报规则一致。远程办公期间的工作时间按实际工作内容填报工时，与在公司办公无区别。

### 3.4 审批权限与时限

单日外勤由直属上级审批；连续外勤超过3个工作日的，需部门负责人审批。单日远程办公由直属上级审批；周期性远程办公（每周固定天数）需部门负责人和HR双重审批。审批应在提交后1个工作日内完成；紧急外勤可先电话沟通后补审批。

## 4. 例外情况

**情况一：紧急客户故障**。因客户系统故障等紧急情况需要立即外出支持的，可先外出并在2小时内补交外勤审批；事后补审批需附客户故障工单或沟通记录。

**情况二：疫情或公共卫生事件**。因疫情等公共卫生事件需要全员远程办公的，由公司统一发布通知，无需个人提交远程办公审批。

**情况三：恶劣天气导致无法到岗**。因台风、暴雪等恶劣天气导致无法到公司办公的，经公司统一通知后，当日可转为远程办公，无需单独审批。

## 5. 处罚与追责

员工未经审批擅自外勤或远程办公的，当日考勤按旷工处理。员工在外勤/远程办公期间失联超过2小时且无合理解释的，按早退处理。员工远程办公期间从事与工作无关活动的（如长时间不在线、响应超时），经核实后扣减当日绩效并取消当月远程办公资格。

## 6. 附则

本规则自2026年1月1日起施行，由人力资源部负责解释。本规则与打卡规则与异常认定、考勤异常申报流程配套使用。远程办公政策每年至少评估1次，根据业务需要和员工反馈调整。

# 加班考勤记录规则

## 1. 适用范围

本规则适用于公司全体员工的加班考勤管理，涵盖工作日延长加班、休息日加班和法定节假日加班三种类型。涉及加班审批、加班打卡、加班工时核算、加班费或调休结算等全流程管理。

不适用本规则的情形：高管（VP及以上）的加班不单独核算；实行不定时工时制的岗位（如销售外勤）不执行加班审批，按合同约定执行。

## 2. 定义与术语

- **加班**：员工在标准工作时间之外，经批准继续工作的时间。
- **工作日延长加班**：标准工作日（周一至周五）下班后继续工作的时间。
- **休息日加班**：周六、周日工作的全部时间。
- **法定节假日加班**：国家法定节假日工作的全部时间。
- **加班审批**：员工加班前或加班后提交的、包含加班时间、原因、预计产出等的审批单。
- **加班打卡**：加班期间通过考勤系统记录的上下班时间。
- **调休**：以休息替代加班费的方式，1小时加班可兑换1小时调休。

## 3. 核心规则

### 3.1 加班审批规则

员工加班须提前提交加班审批，紧急情况下可在加班结束后2个工作日内补办。工作日延长加班单次不超过3小时，月度累计不超过36小时。休息日加班须提前1个工作日提交审批。法定节假日加班须提前3个工作日提交审批，且须经部门负责人和HR双重审批。

### 3.2 加班打卡规则

加班期间须完成加班打卡：开始加班时打卡一次，结束加班时打卡一次。加班打卡地点与正常打卡地点一致（公司、外勤地点或远程办公地址）。加班打卡时间以考勤系统服务器时间为准。加班打卡记录与加班审批时间偏差超过30分钟的，须书面说明原因。

### 3.3 加班工时核算

工作日延长加班：从标准下班时间（18:00）开始计算，扣除晚餐时间（30分钟），实际加班时间按小时计。休息日加班：从实际开始工作时间到结束时间，扣除午餐和晚餐各30分钟，按实际工作小时计。法定节假日加班：从实际开始工作时间到结束时间，按实际工作小时计（不扣除用餐时间）。

### 3.4 加班费与调休结算

工作日延长加班：优先安排调休，不调休的按1.5倍工资结算。休息日加班：优先安排调休，不调休的按2倍工资结算。法定节假日加班：按3倍工资结算，不调休。调休有效期为加班发生日起6个月内，逾期未使用的自动转为加班费结算。

## 4. 例外情况

**情况一：项目交付前紧急加班**。项目进入交付前2周冲刺期，经项目经理和部门负责人共同确认后，工作日延长加班月度累计上限可临时提升至48小时，但须在项目计划中预先声明。

**情况二：系统故障或紧急事件处理**。因生产系统故障、安全事件等需要紧急处理的，可先加班后补办审批，但须在事件结束后2个工作日内完成补办。

**情况三：出差期间的加班**。员工出差期间如需加班，按当地工作时间和加班规则执行；出差地与公司所在地时区差异超过3小时的，按当地时间计算。

## 5. 处罚与追责

员工未经审批擅自加班的，加班工时不予认可，不结算加班费和调休。员工虚报加班时间（打卡记录与实际工作时间不符）的，按异常工时处理，严重者给予警告处分。部门负责人批准明显不合理的加班申请（如连续多日超上限）的，纳入管理者考核。

## 6. 附则

本规则自2026年1月1日起施行，由人力资源部负责解释。本规则与考勤管理制度、外勤与远程办公考勤规则配套使用。加班费结算周期为每月随工资发放，调休在系统中实时记录。本规则每年至少修订1次。

# 迟到早退处罚办法

## 1. 适用范围

本办法适用于公司全体标准工时制和弹性工时制员工的迟到、早退行为的认定与处罚。综合工时制和轮班制员工参照执行，具体认定标准由各部门根据实际排班制定细则。涉及试用期员工、实习生的，按本办法执行；涉及外包人员的，按合同约定执行。

本办法不适用于以下情形：因公司统一通知的恶劣天气、交通管制、公共卫生事件等不可抗力导致的迟到；因公外出已获批准的；高管（VP及以上）的战略性外出。

## 2. 定义与术语

- **一般迟到**：实际到岗时间比规定上班时间晚5分钟至30分钟。
- **严重迟到**：实际到岗时间比规定上班时间晚30分钟至2小时。
- **一般早退**：实际离岗时间比规定下班时间早5分钟至30分钟。
- **严重早退**：实际离岗时间比规定下班时间早30分钟至2小时。
- **累计次数**：以自然月为统计周期，统计员工当月迟到和早退的总次数。
- **处罚阶梯**：根据累计次数不同，处罚力度逐级递增的规则。

## 3. 核心规则

### 3.1 迟到认定与处罚

一般迟到：每次扣减绩效0.5分，不计入旷工。严重迟到：每次扣减绩效2分，按旷工半天处理（扣减当日工资50%）。迟到2小时以上：按旷工半天处理，扣减当日工资50%并扣减绩效3分。

### 3.2 早退认定与处罚

一般早退：每次扣减绩效0.5分，不计入旷工。严重早退：每次扣减绩效2分，按旷工半天处理（扣减当日工资50%）。早退2小时以上：按旷工半天处理，扣减当日工资50%并扣减绩效3分。

### 3.3 累计处罚阶梯

员工当月迟到或早退累计3次以内的，按单次标准执行。累计4-6次的，从第4次起每次扣减绩效1分（一般迟到/早退）或3分（严重迟到/早退）。累计7-10次的，从第7次起每次扣减绩效2分（一般迟到/早退）或4分（严重迟到/早退），并通报批评。累计11次以上的，视为严重违纪，月度绩效降一档，并约谈部门负责人。

### 3.4 全勤奖取消规则

员工当月出现任何1次迟到、早退、旷工或请假记录的，当月全勤奖金200元取消。员工当月迟到或早退累计超过3次的，除取消当月全勤奖外，额外扣减季度全勤奖资格。

## 4. 例外情况

**情况一：首次迟到/早退**。员工入职后首次出现迟到或早退的，给予口头提醒，不扣绩效、不影响全勤奖。该豁免仅适用1次。

**情况二：交通意外或突发疾病**。员工因交通事故、突发疾病等不可预见原因导致迟到或早退的，提供相关证明（如医院诊断、交警证明）后，经HR核实可免除处罚。

**情况三：哺乳期女员工**。哺乳期女员工（婴儿未满1周岁）因哺乳需要迟到或早退的，每日可弹性30分钟，不计入迟到早退统计。

## 5. 处罚与追责

员工对迟到早退处罚有异议的，可在收到处罚通知后5个工作日内向HR申诉。HR在5个工作日内完成复核并给出结论。员工连续2个月累计迟到早退超过10次的，纳入部门负责人管理能力评估。部门负责人对本部门员工迟到早退情况隐瞒不报或包庇的，扣减管理津贴。

## 6. 附则

本办法自2026年1月1日起施行，由人力资源部负责解释。本办法与考勤管理制度配套使用；遇冲突时以本办法为准。本办法每年至少修订1次，根据实际执行情况和员工反馈调整处罚标准。

# 考勤异常申报流程

## 1. 流程目的

为员工提供对考勤异常（如漏打卡、打卡失败、地点异常、时间异常等）进行标准化申报的路径，确保员工的正常出勤不被误记为异常，同时通过流程约束减少虚假申报。目标是使考勤异常申报处理时长不超过3个工作日，申报通过率达到合理水平。

## 2. 适用场景

- 员工忘记打卡或打卡失败导致的考勤记录缺失
- 考勤设备故障导致的无法正常打卡
- 打卡地点与登记地址偏差导致的地点异常
- 因公外出未能按时打卡
- 系统误判导致的考勤异常标记
- 其他合理原因导致的考勤记录与实际出勤不符

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 员工 | 发现异常后及时申报，提供必要证据 |
| 直属上级 | 初审申报内容的真实性和合理性 |
| 部门负责人 | 对复杂或高频异常进行复核 |
| 行政部 | 出具设备故障证明，处理地点异常核查 |
| HR | 终审责任人，处理申诉和争议 |

## 4. 操作步骤

### Step 1: 发现异常并确认

- 操作人：员工
- 输入：考勤系统中的异常标记
- 动作：登录考勤系统查看"我的考勤"，确认异常类型（漏打卡/地点异常/时间异常等）；核对异常日期是否与实际出勤一致；收集相关证据（如企业IM在线记录、工作产出记录等）。
- 输出：确认异常类型和日期
- 时限：发现异常后1个工作日内

### Step 2: 填写异常申报单

- 操作人：员工
- 输入：异常信息和证据
- 动作：进入"考勤异常申报"模块，选择异常类型和日期；填写异常原因（不少于50字）；上传证据材料（如设备故障截图、外出审批单、企业IM聊天记录等）。
- 输出：完整的异常申报单
- 时限：30分钟内完成

### Step 3: 直属上级初审

- 操作人：直属上级
- 输入：员工提交的申报单
- 动作：核实员工所述异常原因是否属实；查看当日工作安排和产出记录；判断证据是否充分；做出"同意/驳回/转复核"决定。
- 输出：初审意见
- 时限：2个工作日内

### Step 4: 部门负责人复核（必要时）

- 操作人：部门负责人
- 输入：直属上级转交的申报单
- 动作：审视初审意见的合理性；对高频异常（同一员工当月超过3次）进行重点关注；做出"同意/驳回"决定。
- 输出：复核意见
- 时限：3个工作日内

### Step 5: 系统更新与归档

- 操作人：系统管理员
- 输入：审批通过的申报单
- 动作：在考勤系统中修正异常记录；生成处理日志；归档申报单和证据材料。
- 输出：已修正的考勤记录
- 时限：审批通过后1个工作日内

## 5. 异常处理

**异常一：员工频繁申报异常**。同一员工当月申报异常超过3次的，从第4次起需部门负责人审批；超过5次的，HR介入调查是否存在系统性问题（如员工打卡习惯差、设备频繁故障等）。

**异常二：证据不足**。员工申报时未提供充分证据的，直属上级可要求补充证据；补充期限为2个工作日；逾期未补充的，申报自动驳回。

**异常三：系统批量异常**。因系统升级或批量配置错误导致多名员工同时出现考勤异常的，由行政部统一出具证明，批量处理，无需员工逐个申报。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 员工发现异常 | 1个工作日内 |
| 直属上级初审 | 2个工作日内 |
| 部门负责人复核 | 3个工作日内 |
| 系统更新 | 审批通过后1个工作日内 |
| 整体闭环 | 不超过5个工作日 |

## 7. 相关表单与系统

- 考勤异常申报单
- 设备故障证明（行政部出具）
- 外出审批单（关联查询）
- 考勤管理系统的"异常申报"模块
- 处理日志归档库

# 月度考勤汇总流程

## 1. 流程目的

为人力资源部门提供标准化的月度考勤数据汇总、核对和报送流程，确保每月考勤数据准确、完整、及时，为薪酬核算、绩效评估、全勤奖发放等下游业务提供可靠的数据基础。目标是使月度考勤汇总在次月5日前完成、数据准确率达到99.5%以上、薪酬核算延迟率为0%。

## 2. 适用场景

- 每月末对当月考勤数据的汇总与核对
- 考勤异常处理完成后的最终数据锁定
- 向薪酬部门提供考勤数据用于工资核算
- 向管理层提供考勤分析报告
- 年度考勤数据的月度累积

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| HR考勤专员 | 汇总总责任人，执行数据汇总、核对和报送 |
| 部门考勤联络人 | 协助核对本部门考勤数据，反馈异常 |
| 薪酬专员 | 接收考勤数据，用于工资核算 |
| 系统管理员 | 维护考勤系统，处理数据导出和格式转换 |
| 行政部 | 提供设备故障证明、外勤记录等辅助材料 |

## 4. 操作步骤

### Step 1: 数据导出

- 操作人：HR考勤专员
- 输入：考勤系统中的原始打卡数据
- 动作：每月1日上午导出上月全部考勤数据（含打卡记录、异常标记、审批记录、补卡记录）；导出格式为Excel，包含员工编号、姓名、部门、每日打卡时间、异常类型、审批状态等字段。
- 输出：原始考勤数据表
- 时限：每月1日上午完成

### Step 2: 异常数据清理

- 操作人：HR考勤专员
- 输入：原始考勤数据表
- 动作：筛选出所有标记为"异常"的记录；对照异常申报审批结果，确认已处理的异常是否已修正；对未处理的异常，联系相关部门考勤联络人确认；生成"待处理异常清单"。
- 输出：异常数据清理后的考勤表 + 待处理异常清单
- 时限：每月2日前完成

### Step 3: 部门核对

- 操作人：部门考勤联络人 + HR考勤专员
- 输入：清理后的考勤表
- 动作：HR将考勤表分发给各部门考勤联络人；各部门在2个工作日内核对本部门数据，重点确认：漏打卡已补卡、外勤已审批、请假已关联、加班已审批；反馈核对结果和疑问。
- 输出：各部门核对确认表
- 时限：每月4日前完成

### Step 4: 数据锁定与报送

- 操作人：HR考勤专员
- 输入：各部门核对确认后的考勤表
- 动作：汇总各部门确认结果，处理剩余疑问；生成最终版"月度考勤汇总表"；在系统中锁定当月考勤数据（锁定后不可修改）；将汇总表报送薪酬部门。
- 输出：月度考勤汇总表（锁定版）
- 时限：每月5日前完成

### Step 5: 薪酬核算对接

- 操作人：薪酬专员
- 输入：月度考勤汇总表
- 动作：按考勤数据核算工资（迟到扣款、全勤奖、加班费、旷工扣款等）；核对考勤数据与薪酬系统的对接字段；发现数据不一致的，联系HR考勤专员核实。
- 输出：工资核算草稿
- 时限：每月8日前完成

### Step 6: 考勤分析报告

- 操作人：HR考勤专员
- 输入：月度考勤汇总表
- 动作：生成考勤分析报告，包含：全勤率、迟到早退率、旷工率、加班时长分布、各部门考勤健康度排名；提交HR负责人审阅。
- 输出：月度考勤分析报告
- 时限：每月10日前完成

## 5. 异常处理

**异常一：部门核对发现批量数据错误**。如某部门多人同一日期打卡异常，可能是设备故障或系统问题；联系行政部出具证明，批量修正。

**异常二：薪酬核算发现考勤数据与系统不一致**。可能是数据导出时格式转换错误；核对原始导出文件和系统记录，重新导出修正。

**异常三：锁定后发现遗漏异常**。考勤数据锁定后原则上不可修改；如确需修改（如重大遗漏），须经HR负责人和部门负责人双重审批，在系统中解锁修正并留痕。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 数据导出 | 每月1日上午 |
| 异常清理 | 每月2日前 |
| 部门核对 | 每月4日前 |
| 数据锁定与报送 | 每月5日前 |
| 薪酬核算对接 | 每月8日前 |
| 分析报告 | 每月10日前 |

## 7. 相关表单与系统

- 月度考勤汇总表
- 待处理异常清单
- 各部门核对确认表
- 考勤分析报告模板
- 考勤管理系统
- 薪酬管理系统（对接用）

# 补卡申请流程

## 1. 流程目的

为员工因合理原因未能正常打卡时提供标准化的补卡申请路径，保障员工的正常出勤记录不被遗漏，同时通过次数限制和审批约束防止补卡被滥用。目标是使补卡申请处理时长不超过2个工作日，月度补卡率控制在5%以内。

## 2. 适用场景

- 员工忘记打卡（上班或下班）
- 考勤设备故障导致无法打卡
- 手机APP故障或网络问题导致打卡失败
- 因公外出未能按时打卡
- 其他合理原因导致的打卡记录缺失

不适用场景：员工迟到或早退后故意不打卡、试图通过补卡规避处罚的；员工代打卡或请他人代打卡后补卡的。

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| 员工 | 发现漏打卡后及时申请补卡，提供必要证据 |
| 直属上级 | 审核补卡申请的真实性和合理性 |
| 部门负责人 | 对高频补卡员工进行复核和约谈 |
| 行政部 | 出具设备故障证明（涉及设备故障时） |
| 系统管理员 | 在系统中执行补卡操作并留痕 |

## 4. 操作步骤

### Step 1: 发现漏打卡

- 操作人：员工
- 输入：考勤系统中的打卡记录
- 动作：每日下班前查看当日考勤记录，确认上班卡和下班卡是否都已成功记录；发现漏打卡的，立即记录漏打的具体时间（如"早上9:05到公司但忘了打卡"）。
- 输出：确认漏打卡的日期和时段
- 时限：发现后立即记录

### Step 2: 填写补卡申请

- 操作人：员工
- 输入：漏打卡信息和证据
- 动作：登录考勤系统进入"补卡申请"模块；选择漏打卡日期和时段（上班/下班）；填写补卡原因（不少于30字）；上传证据（如企业IM在线记录、同事证明、工作产出记录等）。
- 输出：完整的补卡申请单
- 时限：漏打卡后2个工作日内

### Step 3: 直属上级审批

- 操作人：直属上级
- 输入：补卡申请单
- 动作：核实员工所述漏打卡原因是否属实；查看当日工作安排和产出记录；判断证据是否充分；做出"同意/驳回"决定。驳回时需说明具体原因。
- 输出：审批结果
- 时限：2个工作日内

### Step 4: 部门负责人复核（高频补卡时）

- 操作人：部门负责人
- 输入：直属上级同意的补卡申请
- 动作：对同一员工当月补卡超过2次的申请进行复核；判断是否存在习惯性漏打卡；必要时与员工面谈提醒；做出"同意/驳回"决定。
- 输出：复核结果
- 时限：3个工作日内

### Step 5: 系统补卡与归档

- 操作人：系统管理员
- 输入：审批通过的补卡申请
- 动作：在考勤系统中执行补卡操作，补录打卡时间；系统自动标记为"补卡"（与正常打卡区分）；生成补卡日志归档。
- 输出：已补卡的考勤记录
- 时限：审批通过后1个工作日内

## 5. 异常处理

**异常一：员工当月补卡超过3次**。从第4次起，补卡申请自动转部门负责人审批；超过5次的，HR介入调查是否存在系统性问题（如员工打卡习惯差、设备频繁故障等），并约谈员工。

**异常二：补卡申请被驳回**。员工对驳回有异议的，可在3个工作日内向部门负责人申诉；申诉期间不影响其他正常考勤记录。

**异常三：批量补卡需求**。因系统故障导致多名员工同一日期打卡异常的，由行政部统一出具证明，系统管理员批量补卡，无需员工逐个申请。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 员工申请 | 漏打卡后2个工作日内 |
| 直属上级审批 | 2个工作日内 |
| 部门负责人复核 | 3个工作日内 |
| 系统补卡 | 审批通过后1个工作日内 |
| 整体闭环 | 不超过5个工作日 |

## 7. 相关表单与系统

- 补卡申请单
- 设备故障证明（行政部出具）
- 考勤管理系统的"补卡申请"模块
- 补卡日志归档库

# 考勤打卡常见问题

## Q1: 我每天必须打几次卡？什么时候打？

**简答**：标准工时制每天2次：上班卡和下班卡；上班打卡在8:45-9:15，下班打卡在17:45-18:15。

**详细说明**：
标准工时制员工每日须完成2次打卡：上班打卡（到公司时）和下班打卡（离开公司时）。打卡有15分钟的缓冲期：上班打卡允许范围是8:45-9:15，下班打卡允许范围是17:45-18:15。在缓冲区内打卡视为正常；超出缓冲区但在1小时内的，计为轻微异常（不扣绩效但记录留痕）；超出1小时的按迟到/早退规则处理。

弹性工时制员工核心时段10:00-16:00必须在岗，打卡范围是8:00-10:00上班、16:00-20:00下班。综合工时制员工每周至少打卡3次，不强制每日打卡。

**相关制度**：打卡规则与异常认定.md

## Q2: 打卡方式有哪些？可以用手机吗？

**简答**：公司考勤终端（指纹/人脸识别）和手机APP定位打卡两种方式；外勤和远程办公时用手机APP。

**详细说明**：
公司办公区域打卡主要通过考勤终端完成（指纹或人脸识别，部分楼层两者都支持）。手机APP打卡主要用于：外勤打卡（定位半径不超过500米）、远程办公打卡（定位偏差不超过200米）。

手机APP打卡需要提前在系统中登记打卡地址；首次使用时需完成实名认证和人脸识别绑定。PC端网页打卡仅作为备用方案，在考勤终端和手机APP均不可用时使用，需经行政部临时授权。

**相关制度**：打卡规则与异常认定.md

## Q3: 我忘了打卡怎么办？能补吗？

**简答**：可以补卡，但需在漏打卡后2个工作日内申请；当月补卡超过3次需要部门负责人审批。

**详细说明**：
漏打卡后应立即通过"补卡申请流程"申请补录。补卡申请需要：选择漏打卡日期和时段、填写原因（不少于30字）、上传证据（如企业IM在线记录、同事证明等）。直属上级2个工作日内审批。

注意补卡次数限制：当月第1-2次补卡由直属上级审批即可；第3次起自动转部门负责人审批；超过5次的HR会介入调查。频繁补卡不仅影响自己，也会让管理者对你产生"考勤习惯差"的印象。

**相关制度**：补卡申请流程.md

## Q4: 打卡地点不对被标异常了，怎么处理？

**简答**：可能是定位偏差或地址登记错误；先检查手机定位是否开启，再核对系统登记的地址；如确属误判，走考勤异常申报流程。

**详细说明**：
打卡地点异常的常见原因：
1. **手机定位未开启**：确保手机GPS和定位服务已开启
2. **登记地址与实际不符**：如公司搬迁后地址未更新，联系行政部修正
3. **定位偏差**：部分手机定位精度不足，建议在办公区域中心位置打卡
4. **VPN或代理影响**：使用VPN时可能导致定位异常

如果确认是系统误判（如明明在公司却被标异常），通过"考勤异常申报流程"提交申诉，附定位截图和实际位置照片。行政部会核查基站定位和GPS定位的差异。

**相关制度**：考勤异常申报流程.md

## Q5: 出差期间怎么打卡？

**简答**：出差期间通过手机APP外勤打卡；定位半径不超过外勤地点500米；超过4小时的外勤需填写工作日志。

**详细说明**：
出差打卡分两种情况：
1. **当日往返的短期出差**：出发时在公司打卡（或手机APP打卡），到达外勤地点后手机APP外勤打卡，返回公司后下班打卡
2. **连续多日的长期出差**：每日通过手机APP在外勤地点打卡（上班+下班），无需回公司打卡

外勤打卡的定位半径是500米，所以即使住在离客户较远的酒店，只要在客户现场打卡即可。单日外勤超过4小时的，需在系统中填写外勤工作日志（不少于50字），记录当天工作内容。

**相关制度**：外勤与远程办公考勤规则.md

## Q6: 远程办公怎么打卡？有什么要求？

**简答**：远程办公需提前1个工作日审批；每日2次打卡（上班+下班）；打卡地址偏差不超过200米；需保持企业IM在线。

**详细说明**：
远程办公不是"想在家就在家"，需要提前申请：
1. 提前1个工作日提交远程办公审批，说明原因和工作安排
2. 审批通过后，在系统中登记远程办公地址
3. 远程办公期间每日打卡（上班+下班），地址偏差不超过200米
4. 保持企业IM在线，响应时间不超过30分钟
5. 单日远程办公不超过8小时，月度累计不超过当月工作日总数的40%

远程办公期间的工作产出和响应速度会被管理者关注；如果长期远程办公但产出下降，管理者有权取消远程办公资格。

**相关制度**：外勤与远程办公考勤规则.md

## Q7: 打卡记录和实际时间对不上，谁的问题？

**简答**：以考勤系统服务器时间为准；如确有明显偏差（超过5分钟），联系系统管理员核查。

**详细说明**：
考勤系统的打卡时间以服务器时间为准，不是手机时间。如果打卡记录与你记忆中的时间有明显偏差（超过5分钟），可能原因：
1. **手机时间与服务器时间不同步**：手机时间设置错误
2. **网络延迟**：打卡时网络不稳定，导致记录时间有偏差
3. **系统bug**：极少数情况下系统记录异常

建议每次打卡后查看系统显示的打卡时间，如有异常立即截图保留证据，并联系系统管理员核查。系统管理员可调阅打卡日志，核对终端时间和服务器时间的差异。

**相关制度**：打卡规则与异常认定.md

## Q8: 我可以代同事打卡吗？或者让同事帮我打？

**简答**：绝对不可以，代打卡是严重违纪行为，一经发现记过，累计2次解除劳动合同。

**详细说明**：
代打卡（包括让同事在公司打卡而自己在家、用照片骗过人脸识别、使用虚拟定位软件等）属于最严重的考勤违规之一。原因：
1. 考勤记录是工资、绩效、全勤奖的依据，代打卡等于骗取经济利益
2. 涉及信息安全（使用他人账号登录系统）
3. 破坏团队公平性（按时出勤的员工和代打卡的员工获得同样待遇）

公司会定期抽查打卡记录（如对比打卡照片、分析打卡地点模式），技术手段也能识别虚拟定位等作弊行为。不要心存侥幸。

**相关制度**：考勤管理制度.md

# 考勤异常常见问题

## Q1: 考勤异常有哪些类型？分别怎么处理？

**简答**：常见异常类型：漏打卡、迟到、早退、旷工、地点异常、时间异常；处理方式从自行补卡到申报审批不等。

**详细说明**：
考勤异常按类型和处理方式分类：
- **漏打卡**：忘记打卡或打卡失败，走"补卡申请流程"
- **迟到/早退**：超出打卡缓冲区的，按迟到早退处罚办法处理
- **旷工**：未请假缺勤，按旷工规则处理（扣工资+绩效）
- **地点异常**：打卡地点与登记地址偏差过大，走"考勤异常申报流程"
- **时间异常**：打卡时间与实际工作时间明显不符，走"考勤异常申报流程"
- **系统误判**：系统错误标记的异常，联系行政部或系统管理员核查

大多数异常（漏打卡、地点偏差）通过补卡或申报即可解决；涉及处罚的（迟到、旷工）需要按相应制度执行。

**相关制度**：考勤异常申报流程.md

## Q2: 我的考勤被标异常了，但我明明正常出勤了，怎么办？

**简答**：先确认异常类型，收集证据（企业IM在线记录、工作产出、同事证明等），然后通过对应流程申诉。

**详细说明**：
被误判为考勤异常时，处理步骤：
1. **确认异常类型**：登录系统查看具体是什么异常（漏打卡/地点异常/时间异常等）
2. **收集证据**：
   - 企业IM在线记录（证明当日在线工作）
   - 工作产出（代码提交、文档、邮件等）
   - 同事证明（如"当日一起开会"）
   - 系统截图（如打卡记录显示成功但系统仍标异常）
3. **选择流程**：漏打卡走"补卡申请"，其他异常走"考勤异常申报"
4. **提交申诉**：填写原因、上传证据
5. **等待审批**：直属上级2个工作日内处理

注意：申诉期间该异常不直接产生处罚；但如果是真实的迟到/旷工，申诉不会改变结果。

**相关制度**：考勤异常申报流程.md

## Q3: 考勤异常会影响我的工资和绩效吗？

**简答**：漏打卡补卡后不影响；迟到/早退扣绩效；旷工扣工资+绩效；地点异常修正后不影响。

**详细说明**：
不同异常对工资和绩效的影响：
- **漏打卡（已补卡）**：不影响工资和绩效
- **迟到/早退**：每次扣减绩效0.5-2分（按严重程度），取消当月全勤奖
- **旷工**：旷工半天扣当日工资50%+绩效3分；旷工1天扣当日工资100%+绩效5分
- **地点异常（已修正）**：不影响工资和绩效
- **时间异常（已修正）**：不影响工资和绩效

连续2个月出现考勤异常（迟到/早退累计超过10次）的，纳入部门负责人管理能力评估。所以偶尔一次异常不用太担心，但频繁异常需要重视。

**相关制度**：考勤管理制度.md、迟到早退处罚办法.md

## Q4: 设备故障导致打卡失败，算我的异常吗？

**简答**：不算，但需要2个工作日内向行政部报备，由行政部出具故障证明后按正常出勤处理。

**详细说明**：
因考勤设备故障（指纹机失灵、人脸识别失败、网络中断等）导致的打卡失败，员工不承担责任。处理流程：
1. 故障发生时立即截图或拍照保留证据
2. 2个工作日内向行政部报备（可通过企业微信或OA）
3. 行政部核查后出具"设备故障证明"
4. 凭证明在系统中标记为"设备故障-正常出勤"

注意：如果设备故障但你没有报备，系统会按漏打卡处理；所以即使确定是设备问题，也要走报备流程。

**相关制度**：打卡规则与异常认定.md

## Q5: 我能查到别人的考勤异常吗？

**简答**：普通员工只能查自己的；项目经理可查本项目成员的；部门负责人可查本部门的；HR可查全公司。

**详细说明**：
考勤异常查询权限严格按角色：
- **员工**：仅本人考勤异常
- **项目经理**：本项目成员的考勤异常（用于团队管理）
- **部门负责人**：本部门员工的考勤异常
- **HR**：全公司考勤异常（用于汇总分析和制度执行）

查询他人考勤异常需要合理的业务理由（如项目经理管理团队、HR做月度汇总），不得出于好奇或八卦目的查询。违规查询他人考勤数据的，按信息安全制度处理。

**相关制度**：考勤管理制度.md

## Q6: 考勤异常申报被驳回了，还能再申诉吗？

**简答**：可以申诉一次；如有新证据可二次申诉；同一事项一般只受理一次复议。

**详细说明**：
考勤异常申报被驳回后的申诉路径：
1. **首次申诉**：对直属上级的驳回决定不服，可向部门负责人申诉，3个工作日内处理
2. **二次申诉**：对部门负责人的决定仍不服，可向HR申诉，5个工作日内处理
3. **最终结论**：HR的决定为最终结论

申诉时需要提供新的证据或更充分的说明；如果只是重复之前的理由，申诉通过概率很低。建议被驳回后先与直属上级沟通，了解驳回的具体原因，有针对性地补充材料。

**相关制度**：考勤异常申报流程.md

## Q7: 系统显示我旷工了，但我那天请假了，怎么回事？

**简答**：可能是请假审批未同步到考勤系统；联系HR核查请假单状态，确认后修正考勤记录。

**详细说明**：
请假了但系统显示旷工，常见原因：
1. **请假审批未完成**：请假单还在审批流程中，未同步到考勤系统
2. **请假类型不匹配**：如请的是"事假"但系统按"旷工"处理（某些请假类型需要特殊审批）
3. **系统同步延迟**：请假审批已完成但考勤系统未及时同步
4. **请假单填写错误**：如请的是10月15日但填成了10月16日

处理步骤：先查看自己的请假单状态（是否已完成审批），再核对请假日期；如确认是系统问题，联系HR和系统管理员核查并修正。

**相关制度**：考勤管理制度.md

## Q8: 考勤异常记录会保留多久？影响我以后吗？

**简答**：考勤记录保留3年；已修正的异常不影响；未修正的异常（如迟到记录）保留在档案中，可能影响年度评优。

**详细说明**：
考勤数据的保留期限：
- **原始打卡记录**：保留3年
- **异常处理记录**：保留3年（含申诉、补卡、修正等）
- **处罚记录**：保留3年（与绩效档案同步）

已修正的异常（如漏打卡补卡后、地点异常修正后）不会留下负面记录。但未修正的异常（如真实的迟到记录）会保留在考勤档案中，可能影响：
- 年度全勤奖评选
- 年度优秀员工评选（部分奖项要求全年无迟到）
- 晋升评估中的"职业素养"维度

所以尽量保持良好的考勤记录，偶尔一次异常及时修正即可。

**相关制度**：考勤管理制度.md

# 远程办公考勤常见问题

## Q1: 我可以随时申请在家办公吗？需要什么条件？

**简答**：需要提前1个工作日审批；单日远程不超过8小时；月度累计不超过当月工作日总数的40%；需保持企业IM在线。

**详细说明**：
远程办公不是"自由办公"，需要满足以下条件：
1. **提前申请**：提前1个工作日提交远程办公审批，说明原因和工作安排
2. **审批通过**：直属上级审批；周期性远程办公（每周固定天数）需部门负责人和HR双重审批
3. **时间限制**：单日远程办公不超过8小时；月度累计不超过当月工作日总数的40%（如当月22个工作日，最多远程8天）
4. **在线要求**：远程办公期间保持企业IM在线，响应时间不超过30分钟
5. **产出要求**：远程办公期间的工作产出不低于在公司办公的标准

试用期员工申请远程办公需要部门负责人和HR双重审批；部分岗位（如需要现场操作的运维岗）可能不适合远程办公。

**相关制度**：外勤与远程办公考勤规则.md

## Q2: 远程办公期间怎么打卡？和在公司一样吗？

**简答**：远程办公期间通过手机APP或PC端打卡；打卡地址偏差不超过200米；每日2次（上班+下班）。

**详细说明**：
远程办公打卡方式：
- **手机APP打卡**：最常用的方式，基于GPS定位；打卡地址偏差不超过200米
- **PC端打卡**：作为备用，基于IP地址定位；需提前在系统中登记远程办公的IP段

远程办公打卡与在公司打卡的区别：
1. 远程打卡会标记为"远程"（与"正常"区分）
2. 远程打卡的地址偏差容忍度是200米（公司打卡是考勤终端固定位置）
3. 远程打卡需要提前登记地址，未登记的地址打卡会被标为"地点异常"

建议远程办公前先在系统中测试打卡，确认定位正常后再正式开始远程办公。

**相关制度**：打卡规则与异常认定.md

## Q3: 远程办公期间的工作时间怎么算？和在公司一样吗？

**简答**：工作时间计算方式与在公司一致；标准工时制每日8小时；加班需提前审批。

**详细说明**：
远程办公期间的工作时间计算：
- **标准工时**：与在公司一致，每日8小时
- **工时填报**：远程办公期间的工时填报规则与在公司办公无区别，按实际工作内容填报
- **加班**：远程办公期间如需加班，同样需要提前提交加班审批；未经审批的加班工时不予认可
- **午休**：远程办公期间午休1小时不计入工作时间

注意：远程办公期间的工作产出会被管理者关注；如果远程办公期间产出明显低于在公司办公期间，管理者有权要求员工回公司办公或取消远程办公资格。

**相关制度**：外勤与远程办公考勤规则.md

## Q4: 远程办公期间需要参加公司会议怎么办？

**简答**：通过企业IM视频会议参加；会议时间计入工作时间；如因网络问题无法参加的，提前告知会议组织者。

**详细说明**：
远程办公期间的会议安排：
1. **线上会议**：通过企业IM视频会议参加，会议时间正常计入工作时间
2. **线下会议**：如会议需要现场参加，员工应提前评估是否回公司；如必须回公司，当日按正常出勤处理（不按远程办公）
3. **网络问题**：如因家庭网络问题无法参加视频会议，应提前告知会议组织者，并尝试电话参会

建议远程办公期间保持稳定的网络环境；如因网络问题频繁影响工作，管理者可能要求员工改善网络条件或回公司办公。

**相关制度**：外勤与远程办公考勤规则.md

## Q5: 远程办公期间可以带孩子或处理家务吗？

**简答**：远程办公期间应专注于工作；如因家庭原因需要分心，建议请事假或调休，不要一边远程办公一边处理家务。

**详细说明**：
远程办公不等于"在家休息"，员工在远程办公期间应像在公司一样专注于工作。如果因家庭原因（如带孩子、照顾老人）需要频繁分心，建议：
1. 请事假或调休，专心处理家庭事务
2. 申请缩短当日远程办公时间（如只远程办公半天）
3. 与直属上级沟通，调整工作安排

管理者会通过工作产出、响应速度、会议参与度等维度评估远程办公期间的工作状态；如果评估结果不佳，可能取消远程办公资格。

**相关制度**：外勤与远程办公考勤规则.md

## Q6: 远程办公期间失联了怎么办？会被处罚吗？

**简答**：远程办公期间失联超过2小时且无合理解释的，按早退处理；频繁失联的取消远程办公资格。

**详细说明**：
远程办公期间的"失联"定义：企业IM离线超过2小时且无提前告知。处理规则：
- **首次失联**：给予口头提醒
- **再次失联**：按早退处理（扣绩效0.5分）
- **频繁失联（当月超过3次）**：取消当月远程办公资格，并纳入月度提醒

如因网络故障、家庭紧急情况等合理原因失联的，应在恢复联系后第一时间向直属上级说明，并提供相关证据（如网络故障截图）。

**相关制度**：外勤与远程办公考勤规则.md

## Q7: 我可以长期固定每周某几天远程办公吗？

**简答**：可以，但需要申请"周期性远程办公"，经部门负责人和HR双重审批；审批通过后固定执行。

**详细说明**：
周期性远程办公（如每周三、五远程办公）的申请流程：
1. 提交周期性远程办公申请，说明原因、固定远程办公日期、工作安排
2. 直属上级初审
3. 部门负责人和HR双重审批
4. 审批通过后，系统中自动标记固定远程办公日期
5. 固定远程办公日期无需每日单独申请，但如遇特殊情况需回公司的，提前告知直属上级

周期性远程办公的审批有效期为3个月，到期后需重新申请。期间如因工作需要调整远程办公日期，提前1个工作日告知直属上级即可。

**相关制度**：外勤与远程办公考勤规则.md

## Q8: 远程办公期间生病了怎么算？

**简答**：远程办公期间生病的，按病假处理；需提交病假申请和医院证明；病假期间不按远程办公计。

**详细说明**：
远程办公期间生病的处理方式：
1. 立即停止远程办公，向直属上级报告病情
2. 提交病假申请（可通过企业微信或OA）
3. 提供医院诊断证明（病假1天以上需医院证明）
4. 病假期间按病假规则处理（不计入远程办公天数）

注意：远程办公期间生病不要"硬撑"，带病远程办公不仅影响康复，也可能因工作效率低被管理者关注。及时请病假是对自己负责也是对工作负责。

# 考勤纠纷处理案例

## 1. 案例背景

某互联网公司销售部员工李某，2025年9月因考勤问题与公司发生纠纷。李某当月考勤记录显示：迟到3次、早退2次、旷工1天。李某对迟到和早退记录无异议，但对"旷工1天"的认定提出强烈异议，认为该日自己确实出勤了，只是因考勤设备故障未能打卡，且已向直属上级口头报告。

公司按考勤管理制度扣发了李某当月绩效奖金并取消了全勤奖。李某不服，向人力资源部提出申诉，要求撤销旷工认定并补发绩效奖金和全勤奖。

## 2. 涉及问题

- **争议点一**：员工声称因设备故障未打卡但已口头报告，是否构成有效出勤证明？
- **争议点二**：口头报告（无书面记录）能否替代打卡记录作为出勤依据？
- **争议点三**：直属上级是否应承担未督促员工补办手续的管理责任？
- **争议点四**：公司在未充分核实的情况下直接认定旷工，程序是否合规？

## 3. 处理过程

人力资源部在收到李某申诉后，立即启动考勤纠纷核查流程。

**第一步：证据收集**。HR调阅了李某当日的全部可用记录：考勤系统显示当日无打卡记录；企业IM显示李某当日9:15在线、18:20离线；李某当日发送了3封工作邮件（时间分别为10:30、14:20、17:45）；李某的直属上级确认当日李某确实在岗工作，但承认只是口头沟通，未督促李某走补卡流程。

**第二步：制度对照**。HR查阅打卡规则与异常认定："因考勤设备故障导致无法打卡的，员工应在2个工作日内向行政部报备，行政部出具故障证明后，按正常出勤处理。"李某当日未向行政部报备，也未在2个工作日内补卡。

**第三步：多方沟通**。HR分别与李某、直属上级、行政部沟通。李某称"不知道需要向行政部报备，以为跟领导说一声就行"。直属上级承认管理疏忽，未告知李某正确的补卡流程。行政部确认当日该楼层考勤终端确有故障记录（上午9:00-10:30期间3台设备中有1台故障）。

**第四步：综合裁决**。HR综合考虑以下因素做出裁决：
1. 李某当日确实出勤（企业IM在线、工作邮件、上级确认）
2. 当日确有设备故障记录
3. 李某未按制度向行政部报备，存在流程瑕疵
4. 直属上级未履行管理职责，未告知正确流程

最终裁决：撤销李某当日旷工认定，改为"设备故障-正常出勤"；补发当月绩效奖金和全勤奖；对李某进行考勤制度培训（1小时）；对直属上级进行管理能力提醒。

## 4. 结论与启示

1. **制度执行要兼顾事实和程序**：虽然李某未按流程报备，但事实证明其确实出勤且当日确有设备故障，不应机械地按"无打卡=旷工"处理
2. **管理者的告知义务**：直属上级不仅要确认员工在岗，还要告知员工正确的补卡流程；管理疏忽也是纠纷的诱因
3. **证据链的重要性**：企业IM在线记录、工作邮件、设备故障日志等多源证据的综合使用，有助于还原事实真相
4. **培训预防胜于事后补救**：纠纷发生后对李某进行制度培训，对管理者进行提醒，比单纯处罚更能预防类似问题
5. **考勤制度应定期宣贯**：员工"不知道需要向行政部报备"反映出制度宣贯不到位，HR应加强新员工和返岗员工的考勤制度培训
