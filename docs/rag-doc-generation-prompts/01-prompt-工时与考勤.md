# 背景

某互联网/制造业企业的「工时管理系统」正在扩充企业内部知识库,用于驱动一个 RAG(Retrieval-Augmented Generation)智能问答助手。该助手会基于这些文档回答员工/HR/项目经理的提问。

我现在需要你**一次性生成 30 篇文档**,覆盖**工时管理**和**考勤管理**两个主题域。

# 全局规范(所有文档都必须遵守)

## R1. Frontmatter(YAML)

每篇 `.md` 文档**必须**以下面这种 YAML frontmatter 开头:

```yaml
---
title: <文档标题,不含书名号>
category: <一级分类,见 R2>
genre: <文档体裁:policy / sop / faq / case>
version: 1.0
effective_date: 2026-01-01
audience: <受众:all / employee / manager / hr / finance / pm>
tags: [<标签1>, <标签2>, <标签3>]   # 3-5 个,用于 metadata 过滤
acl: public                           # public / internal / confidential
related_docs: [<相关文档名,可空数组>]
---
```

## R2. category 取值(本批次)

只能是以下 2 个值之一:`工时管理` 或 `考勤管理`。具体每篇用哪个见 §6 清单。

## R3. 字数与结构

| 体裁 | 总字数 | 结构要求 |
|------|--------|---------|
| policy | 1500-3000 字 | 6 章(适用范围 / 定义 / 核心规则 / 例外 / 处罚 / 附则) |
| sop | 1200-2500 字 | 7 章(目的 / 适用场景 / 角色职责 / 操作步骤 / 异常处理 / 时效 / 表单) |
| faq | 1500-3000 字 | 至少 8 个 Q&A,每个 Q 配 1 段简答 + 1-3 段详细说明 |
| case | 1000-2000 字 | 5 章(案例背景 / 涉及问题 / 处理过程 / 结论与启示 / 涉及制度) |

## R4. 内容质量约束(关键)

每篇文档必须满足:

- **数字阈值至少 2 个**(如"每月 5 号前提交"、"超过 4 小时算加班"、"3 个工作日内审批")— 用阿拉伯数字便于 BM25 命中
- **业务关键词覆盖至少 5 个**(对应主题域的高频术语)
- **不允许使用具体人名、具体项目名、真实部门名** — 必须用泛指("员工"/"某项目"/"业务部门")
- **禁止抄写其他公司的真实政策** — 必须根据领域常识自创
- **每个章节标题严格用一致的 h2 (`## N. 标题名`) 格式**,便于后续 outline 提取
- **避免空话套话**(如"严格遵守"、"切实落实"应替换为具体动作)
