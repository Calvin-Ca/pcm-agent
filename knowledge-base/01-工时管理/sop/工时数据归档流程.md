# 工时数据归档流程

## 1. 流程目的

为公司工时数据的长期保存、合规留存、历史查询和数据安全提供规范化的归档流程。覆盖月度归档、年度归档、项目归档以及审计调阅等不同场景，明确归档介质、加密方式、保留期限和销毁条件。目标是使工时数据保留期不少于3年（合规相关数据不少于7年）、月度归档100%按时完成、归档检索响应不超过2个工作日。

## 2. 适用场景

- 月度工时审核完成后的常规归档
- 项目结项时的项目工时全量归档
- 年度结算后的年度工时归档与备份
- 离职员工工时数据的人事档案归档
- 外部审计或法务调查时的归档调阅

## 3. 角色与职责

| 角色 | 职责 |
|------|------|
| HR | 归档总责任人，负责归档计划制定与监督 |
| 系统管理员 | 执行系统层归档操作，含数据库备份与加密 |
| 信息安全负责人 | 审定归档介质和加密方式，处理调阅审批 |
| 项目经理 | 项目结项归档时配合提供完整数据 |
| 财务 | 年度结算后核对可计费工时归档准确性 |

## 4. 操作步骤

### Step 1: 归档计划制定

- 操作人：HR
- 输入：年度合规要求、组织变更情况
- 动作：每年1月制定本年度归档计划，明确月度、季度、年度归档时间表；结合监管要求确定不同类别数据的保留期限（一般工时3年、合规工时7年）。
- 输出：年度归档计划表
- 时限：每年1月15日前发布

### Step 2: 月度归档

- 操作人：系统管理员
- 输入：当月已审核完成的工时数据
- 动作：每月15日（确认上月所有工时审核完成）执行月度归档脚本；将上月工时数据同步到归档库；生成MD5校验码并存档；归档库与生产库物理隔离。
- 输出：月度归档完成确认单
- 时限：每月15日前完成

### Step 3: 项目结项归档

- 操作人：项目经理 + 系统管理员
- 输入：已结项项目的全部工时数据
- 动作：项目经理在项目结项申请中勾选"归档工时数据"；系统管理员在结项后5个工作日内将该项目全部工时（含审核日志、申诉记录）打包归档；归档文件存放在项目专属文件夹并加密。
- 输出：项目工时归档包
- 时限：项目结项后5个工作日内

### Step 4: 年度归档与备份

- 操作人：HR + 系统管理员 + 信息安全负责人
- 输入：本年度全部工时数据
- 动作：每年1月底对上一年度工时数据做全量归档；同时做异地备份（不少于2个地理位置）；备份介质类型至少包含云端和离线介质（如加密硬盘）；信息安全负责人核对备份完整性。
- 输出：年度归档与备份完成报告
- 时限：每年1月31日前完成

### Step 5: 离职员工数据归档

- 操作人：HR + 系统管理员
- 输入：离职员工工时数据
- 动作：员工离职手续完成后10个工作日内，将其全部历史工时同步到人事档案模块；保留期限按当地劳动法律最低要求执行；归档后系统中员工工时仍可被项目经理查询但不可修改。
- 输出：离职员工工时已归档的确认
- 时限：离职手续完成后10个工作日内

### Step 6: 归档调阅

- 操作人：申请方 + 信息安全负责人
- 输入：调阅申请（含理由、范围、用途）
- 动作：调阅申请通过OA提交，信息安全负责人审批；批准后系统管理员从归档库提取数据并脱敏；调阅记录留痕，调阅完成后销毁临时副本。
- 输出：批准的调阅数据
- 时限：申请后2个工作日内响应

## 5. 异常处理

**异常一：归档过程中发现数据校验失败**。系统管理员立即停止当次归档操作，回查数据库与归档库差异；若差异源于审核未结束，等待审核完成后重做；源于系统bug的，转研发处理。

**异常二：归档介质损坏或丢失**。立即启动信息安全应急预案；评估数据是否可从其他备份介质恢复；如无法恢复，按公司数据丢失事件应急处理流程上报。

**异常三：跨年度数据查询**。涉及3年以上的历史数据查询，需要从离线介质恢复；提前2个工作日提交查询计划，由系统管理员安排恢复时间窗口。

## 6. 时效要求

| 节点 | SLA |
|------|-----|
| 月度归档 | 每月15日前 |
| 项目归档 | 项目结项后5个工作日内 |
| 年度归档 | 每年1月31日前 |
| 离职员工归档 | 离职后10个工作日内 |
| 归档调阅响应 | 2个工作日内 |
| 数据保留期 | 一般3年、合规7年 |

## 7. 相关表单与系统

- 年度归档计划表
- 月度归档完成确认单
- 项目工时归档包（含审核日志）
- 归档调阅申请单
- 数据销毁记录单
- 工时归档库（独立部署）
- 异地备份系统
